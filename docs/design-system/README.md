# AstroDX 设计系统与布局规范 v0.1

状态：三个样板的开发规范，等待预览验收；未发布。2026-11-14。

## 目标与边界

让人进入页面后，知道「这里是什么、下一步做什么、操作现在进行到哪」。用户已确认先建立规范，再以搜谱页、谱面详情和下载管理器作为样板。保留现有蓝色品牌、深浅色和三种语言，不替换组件库，不重写下载引擎，不迁移全站，不发布。

## 设计原则

1. 内容优先：歌名、搜索结果和任务进度高于装饰、统计和辅助说明。
2. 一个任务区域只有一个主要操作；其他操作使用描边、文本或展开入口。
3. 渐进展示：默认展示常用功能，高级筛选、文件明细、导入教程和错误详情按需展开。
4. 状态即下一步：正在下载可暂停，暂停可继续，失败可重试，文件就绪可保存。
5. 组件状态完整：空、加载、进行、暂停、失败、待保存和完成均有明确反馈；颜色不能独立承担状态含义。
6. 在同一层解决问题：主题值归 token，布局归公共容器，业务行为归业务组件。

## 基础体系

| 项目 | 规则 | 实现位置 |
| --- | --- | --- |
| 色彩 | 沿用 background/card/popover/primary/muted/destructive；业务颜色仅用于版本、难度、曲风等有语义的信息 | packages/ui/src/styles/theme.css |
| 页面宽度 | 列表与详情使用共同的最大宽度 80rem；长文阅读区另限 48rem | layout-page-max / layout-reading-max |
| 页面留白 | 左右 16–24px；上下 24–40px；区块间距 24–32px | layout-gutter / layout-page-padding / layout-section-gap |
| 字体 | 页面标题 28–36px，区块标题 18px，正文 14–16px，辅助信息至少 12px | type-page-title / type-section-title；公共标题组件 |
| 表面 | 页面为 background，主要内容为 card，浮层为 popover；一个区块只用一层主边框 | Surface / ui-surface |
| 圆角 | 控件沿用基础组件；内容表面统一 radius-2xl，减少页面自己指定大圆角 | surface-radius |
| 控件 | 样板中的主要、次要操作和搜索输入实高至少 44px；图标必须有可访问名称 | Button touch / icon-touch |
| 动效 | 沿用 EASE_OUT 和 springSoft；减少动画设置始终有效；不让装饰动画承担状态反馈 | @astrodx/ui/motion |

新增值先修改 token，不在三个样板里复制同一类尺寸。已有其他页面暂不改变默认密度。

## 页面骨架

公共组件位于 packages/ui/src/components/page-layout.tsx：PageShell、PageHeader、Surface。

- 每页一个 main 和 h1；PageHeader 负责标题、用途说明和低优先级统计。
- h2 用于任务区域和内容区块，不用大段说明代替层级。
- 内容块可自然换行；不以隐藏横向溢出掩盖内容超宽。
- 320/390px 为手机，768px 检查平板，1440px 检查桌面；布局按内容空间变化。
- 手机按内容顺序阅读，桌面通过网格并排；不按设备复制两份交互 DOM。

## 样板一：搜谱页

```
搜谱                         页面用途
搜索框  [随机一首]            常用入口
[高级筛选]                   默认收起
已选条件，可逐项清除
结果数量 / 排序 / 多选        结果工具栏
谱面卡片网格
分页
```

搜索与筛选属于同一个表面；排序、多选属于结果工具栏。筛选保持 URL 同步、中文输入法兼容、空结果建议和键盘操作。统计作为轻量元信息，避免与标题、说明组成三段同等醒目的介绍。批量栏仅在有选择时出现，不能改变后台任务的归属。

## 样板二：谱面详情

```
返回搜谱
小封面 | 歌名、作者、版本、难度
下载谱面                     主要任务区域
[下载 / 暂停 / 继续 / 保存] [下载选项]
体积、BGA、线路与必要状态
[导入帮助]                   按需展开
预览 / 手元 / PV / 评论 / 分享  次要操作
[关于这首谱面]               长描述与资源标签按需展开
谱面信息、难度明细与关联谱面
```

手机封面不占满第一屏；主标题、作者和难度在首屏可识别。下载区域与探索、分享区域分开，不把两者放进同一排。介绍文本继续存在于服务器 HTML 和结构化数据中。常用操作显示文字，避免依赖 hover 工具提示。

下载说明只出现一次。待保存不能仅展示一个禁用的下载按钮；格式选择只更新偏好。首次默认 .adx，截图明确标注测试格式。保存已发起不等于文件已落盘，手机分批的确认仍需用户主动完成。

## 样板三：下载管理器

- 全局任务来源统一，详情页正在显示的任务仍可在管理器找到。
- 默认收起为任务入口，显示数量和最需要处理的状态；优先级为待保存、失败、暂停、打包、下载、排队、完成。
- 展开后是有名称的非模态 region；不锁定页面或伪装成 modal。
- 固定头部：名称、数量、收起。一个正文滚动区：任务卡片、记录、帮助。
- 任务卡片统一顺序：任务名和控制 → 当前阶段 → 必要的保存操作 → 文件/诊断详情 → 进度。
- 主要操作文字明确；收起不取消任务，移除完成记录和取消未完成下载分别命名。
- 下载百分比不冒充打包百分比；打包使用不定进度和当前文件名。
- 历史记录明确是「重新下载」，与当前文件的「再次保存」区分。

## 浮动界面与层级

| 层级 | 内容 | 协调规则 |
| --- | --- | --- |
| 内容层 | 页面内容 | 页面本身滚动，不固定大段说明 |
| 导航层 | 顶栏、手机底栏 | 保留安全区；沿用现有浮动底部变量 |
| 任务层 | 批量栏、播放器、下载入口/面板 | 下载入口避让批量栏和展开播放器；面板限制在可视高度内 |
| 模态层 | 菜单、弹层、详情媒体面板 | 由已有 Radix 管理焦点与关闭，不新增手工焦点陷阱 |
| 装饰层 | 看板娘、点击效果 | 不遮挡任务主要操作，不承担操作入口 |

本轮沿用 --floating-bottom、--batch-download-bar-height、--music-player-mobile-reserve，修正管理器内部滚动；不在样板里额外添加固定操作栏。

## 交付与演进

本轮交付规范、公共布局基础、三个真实页面样板、检查记录和默认 .adx 截图。通过后再迁移首页、版本页、说明页和社群等页面。

样板验收：三语言、深浅色、窄屏、长标题、空结果、有筛选、键盘焦点、后台任务、待保存/失败/暂停状态、播放器与批量栏同时出现。功能测试证明行为，浏览器截图证明实际布局；真实手机保存仍是独立验收项。

后续新增页面必须复用 PageShell/PageHeader/Surface，新增业务图案需先补充本规范；已有页面的迁移可以逐步完成。样板验收前，这份 v0.1 允许修订，不作为已经完成全站统一的声明。
