# AstroDX 设计系统与布局规范 v0.5

状态：M2 方向的 4px 微圆角已扩展到主站公共页面、导航与门户；桌面侧栏与本地队列/歌单在开发分支落地，未发布。2026-11-14。

## 目标与边界

让人进入页面后，知道「这里是什么、下一步做什么、操作现在进行到哪」。先以搜谱页、谱面详情和下载管理器验证，再按用户授权扩展到主站其他页面。保留蓝色品牌方向、深浅色、用户强调色和三种语言，不替换组件库，不重写下载引擎，不修改后台 apps/dash，不发布。

## 设计原则

1. 内容优先：歌名、搜索结果和任务进度高于装饰、统计和辅助说明。
2. 一个任务区域只有一个主要操作；其他操作使用描边、文本或展开入口。
3. 渐进展示：默认展示常用功能，高级筛选、文件明细、导入教程和错误详情按需展开。
4. 状态即下一步：正在下载可暂停，暂停可继续，失败可重试，文件就绪可保存。
5. 组件状态完整：空、加载、进行、暂停、失败、待保存和完成均有明确反馈；颜色不能独立承担状态含义。
6. 在同一层解决问题：主题值归 token，布局归公共容器，业务行为归业务组件。

## 基础体系

| 项目 | 规则 | 实现位置 |
| --- | --- | --- |
| 色彩 | 共享基础色不变；样板由 md-seed/background/surface/container/title/outline 等语义角色组织中性表面；业务颜色仅用于版本、难度、曲风等有语义的信息 | packages/ui/src/styles/theme.css；apps/web/src/app/material.css |
| 页面宽度 | 样板列表与详情最大宽度 1200px；长文阅读区另限 48rem | layout-page-max / layout-reading-max |
| 页面留白 | 左右 16–24px；上下 24–40px；区块间距 24–32px | layout-gutter / layout-page-padding / layout-section-gap |
| 字体 | 样板页面标题手机 30px、桌面 32px，详情桌面 34px；区块标题 20px，正文 14–16px，辅助信息至少 12px | type-page-title / type-section-title；公共标题组件 |
| 表面 | Material 样板采用中性背景、白色/深色内容表面、细边框和轻阴影；浮层保留必要阴影 | Surface / ui-surface |
| 圆角 | 样板内容表面、按钮、输入框、任务卡片、管理器与门户统一 4px 微圆角；封面同为 4px | surface-radius |
| 控件 | 触控目标至少 44px；搜谱输入与主要下载操作 48px，次级下载操作 48px；图标必须有可访问名称 | Button touch / icon-touch |
| 动效 | 沿用 EASE_OUT 和 springSoft；减少动画设置始终有效；不让装饰动画承担状态反馈 | @astrodx/ui/motion |

主站通过 RootLayoutShell 的 adx-site / adx-material 标记启用，独立 global-error 同样启用；三个原有样板保留页面/组件语义标记；默认蓝采用靛蓝主操作，其他强调色沿用用户选择；浅色橙/青的主色加深以保证主按钮小字号文字对比度至少 4.5:1。门户从主站 body 继承相同主题，普通菜单和弹层统一4px。播放器圆形播放键、头像、进度环和语义徽章保留形状；门户播放器有明确标记，圆形控件保护同时覆盖本体和门户。新增值先修改 token，不在三个样板里复制同一类尺寸。普通页面保留内容顺序与已有密度；长文保留较窄的阅读宽度。宽页面、页头与页脚上限1200px。

## 页面骨架

公共组件位于 packages/ui/src/components/page-layout.tsx：PageShell、PageHeader、Surface。

- 每页一个 main 和 h1；PageHeader 负责标题、用途说明和低优先级统计。
- h2 用于任务区域和内容区块，不用大段说明代替层级。
- 内容块可自然换行；不以隐藏横向溢出掩盖内容超宽。
- 320/390px 为手机，768px 检查平板，1440px 检查桌面；布局按内容空间变化。
- 手机按内容顺序阅读，桌面通过网格并排；不按设备复制两份交互 DOM。

## 样板一：搜谱页

```
搜谱                         页面用途
搜索框  [随机一首]            常用入口
[高级筛选]                   默认收起
已选条件，可逐项清除
结果数量 / 排序 / 多选        结果工具栏
谱面卡片网格
分页
```

搜索与筛选属于同一个表面；排序、多选属于结果工具栏。筛选保持 URL 同步、中文输入法兼容、空结果建议和键盘操作。统计作为轻量元信息，避免与标题、说明组成三段同等醒目的介绍。批量栏仅在有选择时出现，不能改变后台任务的归属。

## 样板二：谱面详情

```
返回搜谱
小封面 | 歌名、作者、版本、难度
下载谱面                     主要任务区域
[下载 / 暂停 / 继续 / 保存] [下载选项]
体积、BGA、线路与必要状态
[导入帮助]                   按需展开
预览 / 手元 / PV / 评论 / 分享  次要操作
[关于这首谱面]               长描述与资源标签按需展开
谱面信息、难度明细与关联谱面
```

封面使用 contain 完整显示，保持原始比例；横竖封面允许留白，不做填满裁切或悬停放大。封面统一 4px 微圆角，搜谱卡片封面内缩 12px，避免外层裁切；详情主封面与相关推荐同样适用。手机封面不占满第一屏；主标题、作者和难度在首屏可识别。下载区域与探索、分享区域分开，不把两者放进同一排。介绍文本继续存在于服务器 HTML 和结构化数据中。常用操作显示文字，避免依赖 hover 工具提示。

下载说明只出现一次。待保存不能仅展示一个禁用的下载按钮；格式选择只更新偏好。首次默认 .adx，截图明确标注测试格式。保存已发起不等于文件已落盘，手机分批的确认仍需用户主动完成。确认使用文件说明区内独立控件，不能把刚点击的保存按钮原地改成释放数据的确认按钮。大批量确认期间修改格式会关闭确认，必须重新确认新格式。

## 样板三：下载管理器

- 全局任务来源统一，详情页正在显示的任务仍可在管理器找到。
- 默认收起为任务入口，显示数量和最需要处理的状态；优先级为待保存、失败、暂停、打包、下载、排队、完成。
- 展开后是有名称的非模态 region；不锁定页面或伪装成 modal。
- 固定头部：名称、数量、收起。一个正文滚动区：任务卡片、记录、帮助。展开时焦点交给收起按钮，收起时返回任务入口，不创建模态焦点陷阱。
- 任务卡片统一顺序：任务名和控制 → 当前阶段 → 必要的保存操作 → 文件/诊断详情 → 进度。
- 主要操作文字明确；收起不取消任务，移除完成记录和取消未完成下载分别命名。
- 下载百分比不冒充打包百分比；打包使用不定进度和当前文件名。
- 历史记录明确是「重新下载」，与当前文件的「再次保存」区分。

## 浮动界面与层级

| 层级 | 内容 | 协调规则 |
| --- | --- | --- |
| 内容层 | 页面内容 | 页面本身滚动，不固定大段说明 |
| 导航层 | 顶栏、手机底栏 | 保留安全区；沿用现有浮动底部变量 |
| 任务层 | 批量栏、播放器、下载入口/面板 | 下载入口避让批量栏和展开播放器；面板限制在可视高度内 |
| 模态层 | 菜单、弹层、详情媒体面板 | 由已有 Radix 管理焦点与关闭，不新增手工焦点陷阱 |
| 装饰层 | 看板娘、点击效果 | 不遮挡任务主要操作，不承担操作入口 |

本轮沿用 --floating-bottom、--batch-download-bar-height、--music-player-mobile-reserve。手机上的折叠播放器也预留空间；批量栏最多占一半视口，其余内容内部滚动。展开的管理器优先保证自身可用空间，可临时覆盖批量栏或播放器，收起后恢复，不强求多个大面板始终并排可见。折叠入口的叠放高度受视口上限约束。管理器与播放器同层时由任务面板优先，门户菜单/模态层继续位于其上；不额外添加固定操作栏。

## 交付与演进

当前主站覆盖首页、版本、音乐、社群、公告、捐赠、友链、关于、指南、日志、许可、留言、Live2D、谱面预览等页面，以及共用导航、页脚、门户和原有下载样板。首页独立 CSS 模块采用相同4px/中性表面；图像默认 contain，媒体音频封面和播放器封面也完整显示。视频画面不改变适配方式。后台与共享组件库默认值不在本轮范围。

样板验收：三语言、深浅色、窄屏、长标题、空结果、有筛选、键盘焦点、后台任务、待保存/失败/暂停状态、播放器与批量栏同时出现。功能测试证明行为，浏览器截图证明实际布局；真实手机保存仍是独立验收项。

后续新增页面必须复用 PageShell/PageHeader/Surface，新增业务图案需先补充本规范；这份 v0.5 仍允许基于验收修订；代码统一不等同真实手机与外部服务验收完成。


## 公共组件使用示例

```tsx
import { PageShell, PageHeader, Surface } from "@astrodx/ui/components/page-layout";
import { Button } from "@astrodx/ui/components/button";

<PageShell>
  <PageHeader title={copy.title} description={copy.description} meta={copy.count} />
  <Surface aria-labelledby="download-title">
    <h2 id="download-title" className="ui-section-title">{copy.download}</h2>
    <Button size="touch">{copy.start}</Button>
  </Surface>
</PageShell>
```

文字由业务层传入；公共组件不依赖 Next 路由或固定语言。页面特有布局需遵循同一颜色、表面和形状角色；不修改共享组件库的 Button 默认密度。


## 桌面侧栏与播放器

桌面≥1024px采用224px固定侧栏，内容外壳与悬浮播放器避让；导航独立滚动，支持/搜索/随机/语言/设置固定在底部，控件目标44px。手机保留紧凑顶栏、底部导航与完整菜单。首页双栏在1324px以下合为单栏，补偿侧栏占用的宽度，不能用overflow隐藏超宽控件。

播放器面板分当前队列、曲库、我的歌单。浏览版本与当前播放分离；支持立即播放、下一首、追加、移除、重排、清空。本地歌单支持新建/重命名/删除、增删歌曲、保存当前队列和追加到队列。最多50个本地歌单，每个及队列最多500首，重复歌曲去重；存储受限时显示警告。恢复不自动播放。删除与清空采用独立确认，菜单门户位于播放器之上。评论与404根因和验证边界见 comments-404-audit.md，详细设计与验收见 navigation-player-redesign.md。
