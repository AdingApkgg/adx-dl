# 封面配色缓存与渐变预览

本轮实现用户确认的构建端提色、缓存复用、渐变替代模糊方案；未推送、未发布。

- 现有 Sharp 仅在构建脚本中使用，输入限制2MiB、1600万像素，缩为32×32 RGBA后量化。过滤透明和极端明暗边框，派生5个颜色值。所有1934组配色通过强调色/白字≥4.5、深背景/高亮≥4.5、浅背景/正文≥7的对比度检查。
- 配色在独立JSON中缓存，不写入谱面指纹或时间戳。目录在服务端读取时合并，音乐清单仅增加颜色值；客户端不解析像素。来源URL、背景文件大小或imported_at变化会失效；7天后使用ETag/Last-Modified条件验证，同URL换图可用`--revalidate`强制条件验证。失败保留旧记录，失败来源冷却1天。
- 构建默认4并发、单请求10秒、总处理预算120秒；超出预算的条目下次继续，未处理/缺图使用默认色。`--limit`与`--budget-ms`可用于隔离验证。原子写入避免开发预览读到半个文件。
- 主站检查与发布工作流只增加缓存恢复、增量提色步骤；没有触发任何workflow。缓存存储色值及HTTP元数据，不保留整图。
- 详情页浅色与深色主题分别使用对应背景和按钮色；播放器移除了背景图片和blur，用已有动效token对静态渐变做200ms透明度过渡。减少动态效果立即使用单层静态渐变。背景组件memo避免播放进度更新触发重建。

## 实测

远程主机 `localhost-1`，独立预览 `dev-panel-fullscreen-20261114` / 3313。

首次8张：1555ms、8请求、8解码、204540字节。之后1733张：240571ms、68894806字节，预算到时保留193张待处理；续跑193张35076ms、7392464字节。全部1934张已有配色，无失败。

全量暖缓存：8ms、1934复用、0 HTTP请求、0解码、0字节下载。这里8ms指缓存处理及写入，不包含命令启动时间。

远程lint、类型检查、UI59项与主站786项测试通过。浏览器覆盖1440/390/320px、真实配色、浅深主题、切歌后只保留一个渐变层、减少动态效果与无横向溢出。切歌回归用隔离WAV；展示截图另用真实媒体路径。没有以此宣称所有上游音频线路可用。
