# 社区发布验证：远程无头 E2E

开发期间不启动全量验证；准备上生产时集中验证、修复。正常发布无需操作或解锁 Mac Chrome。

## 发布前：完整业务 E2E

复用 `.github/workflows/community-check.yml` 的 `Community check`，不要在同一候选版本上额外手跑相同全套检查。`select.sh` 按完整 PR diff 选择浏览器和恢复验收；UI 改动不启动完整恢复，文档和单元测试文件改动不启动这两项。人工 workflow_dispatch 运行两项。

`test/acceptance/browser.mjs` 使用无头 Chromium，在独立 PostgreSQL、Redis、S3、真实 web/media/control 进程和独立账号上运行。覆盖三种上传、保存、明确选版发布、公开浏览、评论/回复/时间点、论坛、通知、举报、精选、公告和后台权限，以及作者关注/动态/提醒，共 26 步。恢复单独顺序运行，避免与浏览器争抢磁盘。

代码、锁文件、运行配置及镜像层未变化时复用候选的通过记录；合并后核对实际树与部署制品。修改失败项后先定向重跑，最终发布门禁以最终候选为准，不能拼接不同候选的结果。

## 正式发布入口（强制门禁）

```sh
python3 scripts/remote/community-deploy.py
```

部署新版本前先把控制端工作区同步到经过 CI 的目标 `pre` 提交，保持已跟踪文件干净；正式脚本在构建和迁移前核对远端检出提交与控制端 HEAD 完全一致，版本不符就停止，要求更新工具后重试，避免旧工具误验新版。`--verify-current` 只复核既有运行版本，不要求旧应用与新运维源码同一提交。

正式入口会自动完成：`pre` 切换 → web/media 就绪 → 生产登录态无头验收 → 会话和容器清理 → 核对版本与三角色身份 → 标记发布完成。
无需手动追加一次冒烟命令。部署脚本从切换到最终验收全程持有同一把主机锁；缺少协调器上下文的直接调用在拉取、构建前拒绝执行。

`.serving-revision` 在应用就绪后记录实际运行版本，供冒烟识别候选；`.deploy-revision` 只在本轮验收通过后推进，失败保留上一次通过版本。
每轮在 `/home/i/astrodx-community-releases/<releaseId>/` 保存私有 `ready.json`、`acceptance.json`、`accepted.json` 和 `complete.json`。
只有 `complete.json` 与 `.release-status.json` 都为 complete 才能报告发布完成。旧结果、匿名结果、错版本、错脚本哈希、漏场景、未撤销会话、
清理失败、过期收据，以及验收期间任何角色被替换都会被拒绝。receipt 与本轮随机 releaseId、当前版本及三个运行角色绑定，不重用早先的冒烟通过记录。

```sh
# 仅复核当前运行版本，实际经过相同门禁，不构建/迁移/重启
python3 scripts/remote/community-deploy.py --verify-current
```

异常或超时自动令本轮失败，保留正在运行的服务及上一次通过标记，供修复后重试；不会自动回滚不兼容的认证日志读者。
运维部署输出留在生产私有 deploy.log；控制端只返回阶段与非敏感收据。现有 SSH 和代理配置继续使用，不新增 SSH 密钥或公开端点。

## 部署后：默认带生产登录态

单独诊断时可执行：

```sh
scripts/remote/community-smoke.sh
```

默认等同 `--authenticated`。正式协调器会自动调用它，单独运行只做诊断，不写发布完成标记；不会触发新部署，也不启动定时任务。只需 SSH 到构建机和生产机的现有运维权限。Mac 只运行轻量控制脚本和 SSH TCP 转发，Chromium 和所有浏览器操作均在 `localhost-1` 运行。

`community-auth-smoke.py` 自动完成：

1. 核对生产主机 `arch`、运行容器及部署标记。
2. 在生产机启动只读、非 root、移除全部 capabilities 且限额的临时辅助容器，使用当前应用镜像和既有配置；不重启或修改站点。调用应用原有 Better Auth 内部适配器，为现有管理员 **用户 1** 签发本轮专用会话，最长 10 分钟。它属于 SSH 运维签发，不代表重新完成了 QQ、AWMC 或 Passkey 登录。
3. 真正的会话令牌和签名密钥只留在生产机；构建机仅拿到本轮只读代理的随机 capability。代理仅绑定生产宿主机回环地址，通过 SSH 转发访问；请求真实的 `https://adxc.saop.cc`，保留生产现有代理和 HTTPS 校验，覆盖公共入口。没有新增公网认证端点、长期凭据或常驻管理员。
4. 代理仅允许验收页面、静态资源及指定数据接口的 GET/HEAD；生产端拒绝所有业务写入方法，不依赖浏览器自律。拒绝 `/api/auth/*`、设备会话列表和任意转发地址；不向浏览器传递 Set-Cookie 或认证令牌响应头。浏览器同时禁用 service worker 和 WebSocket。
5. 构建机 Chromium 验证匿名流程、管理员身份、通知列表、发帖/评论表单、后台八个入口、讨论板块与举报视图、六项依赖、三个运行角色及最近成功备份。新增本人关注/动态、作者提醒控件与后台私有控制屏障，正式收据要求十组场景。页面异常、意外写入尝试或角色不符均失败，不降级成匿名通过。
6. 浏览器验收后立即撤销该会话，再验证已不可访问且浏览器未持有生产 Cookie。正常、异常和超时路径均清理 SSH 通路和辅助容器；崩溃兜底只按本轮唯一 runId 撤销自建会话。检查既有会话未被工具替换、生产 web 未重启；清理未确认时整个命令失败。

生产端每次使用独立目录 `/home/i/astrodx-verify/auth-smoke/<runId>/`，构建机结果在 `/home/i/astrodx-verify/production-smoke/auth-<runId>/evidence/`。目录为 0700，诊断文件为 0600；构建机的临时 capability 文件结束即删。结果只含阶段、时间、布尔检查及版本/脚本哈希；失败截图可能含账号资料，按私有材料保留，不自动上传 CI artifact。原始生产日志不导出。

浏览器总时限 300 秒；没有完整结果或会话清理证据时明确失败。`toolBaseTree` 是工具仓库 HEAD 的基准，不能冒充部署版本；`productionRevision` 来自本轮生产部署标记。重型产品检查仍只在发布前集中跑，不因为冒烟工具调整重新构建产品。

## 只跑匿名与已有外部会话

```sh
scripts/remote/community-smoke.sh --anonymous
```

该模式不签发会话，只向构建机发送公开冒烟脚本。验证谱面 #1、评论区、下载入口、旧 UUID/用户链接、三语论坛/公告/帮助、匿名私有权限及 320/390 像素布局。结果明确 `authenticated: not-configured`，不满足完整发布门禁。只检查下载入口，不重复下载大原包；完整原包字节与哈希由发布前 E2E 验证。

显式设置 `PRODUCTION_STORAGE_STATE=/构建机上的私有文件` 时仍支持旧的外部会话模式。文件须由远程当前用户所有、0600；只载入 ADXC 安全会话，不读本机 Chrome 配置。正常发布优先使用默认的短时运维模式，不需要保存或续期个人浏览器会话。

构建机复用已装的 Playwright 1.58.2 和 Chromium。工具目录变化可设置 `ACCEPTANCE_PLAYWRIGHT_PATH`；不自动安装、不使用 sudo。首次第三方授权、验证码、真实设备认证、听感和游戏导入仅在对应能力变化时单独验收，不能把运维会话冒烟当作这些流程的证据。
