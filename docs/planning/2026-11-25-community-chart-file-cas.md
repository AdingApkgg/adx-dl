# INOTE 谱面散文件 CAS

现有上传把目录或分别选择的文件装成 ZIP 传输。服务端以整包 SHA-256 保存原件，另外保存预览产物。整包的重打包、不同的文件顺序或不同的压缩方式，都会让里面相同的曲绘、音乐等重新占用对象存储。

## 目标模型

- 上传仍可收散文件、目录、ZIP 和 ADX。ZIP 只是现有传输格式。服务端在有界目录解包和校验，按每个文件的原始字节计算 SHA-256。音乐、曲绘、谱面、视频和附件分别进入私有对象存储。内容相同的文件共用一个对象。
- 一个上传源有一份不可变清单，记录规范化路径、文件大小和 SHA-256。现有作品版本通过来源文件引用清单。公共发布继续固定到作品版本。改曲名、切换公开版本和撤回都无需复制对象。
- 散文件对象沿用对象存储的预算、写入租约、状态与回收流程。文件名和用途留在清单。若复用现有物理对象记录，须按同一存储策略和实际摘要核对对象，避免把某种用途的 MIME 当成文件内容身份。
- 保存前重读对象元数据，确认清单中所有文件均已落盘。写入中断只留下可重试的对象租约。完整清单与来源的关联在同一数据库事务内提交，失败时旧版本仍可读。
- 公共清单和文件接口先检查当前作品与版本的可见性。对象键留在服务端。下载时用同一清单组包，ADX 使用 AstroDX 的单曲目录和约定文件名，ZIP 保留文件原始字节及路径。静态预览仍可使用现有派生产物。

## 迁移顺序

1. 新增对象引用和已提交的清单，先接入新上传。旧原包继续作为可恢复输入。旧版本缺清单时继续走原件下载及 ADX 导出。
2. 在隔离环境验证并发命中同一摘要、写入中断后的恢复、预算对账、清单与预览一致，以及共享素材被一个作品删除后还能供其他作品读取。
3. 补齐备份和恢复。备份按已提交清单去重校验内容，恢复后逐条校验大小及 SHA-256，再验固定版本的下载和撤回。回收同时校验作品、历史版本、迁移清单和正在写入的引用。
4. 现有作品逐批提取并做文件清单对账。未核对的版本保留原件路径。原件退出在线存储需要独立切换验证和明确授权。

目前代码先让现有公开原包可以保存为 ZIP 或打包为 ADX。这份设计还未接入服务端上传和存储生命周期。
