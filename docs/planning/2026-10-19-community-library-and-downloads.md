# 完整大任务规划：谱库、公开谱单与下载中心

日期：2026-10-19。状态：**用户于 2026-10-19 批准完整范围及实施、集中验证修复与正式部署；开发期不运行测试。**

## 1. 一次交付的目标

让用户完成一条连贯流程：从搜索、作者作品或关注动态发现谱面 → 收藏或归入自建谱单 → 按自己的顺序整理 → 明确发布谱单供他人浏览、复制 → 将选中的原始谱包加入下载中心，跨页面查看进度、暂停和重试。

建议将它作为一个持续 10–16 小时量级的完整实现任务，另预留集中验证、故障修复和正式发布窗口；时间仅为范围估计，不作完成时限保证。内部按依赖推进，**不按阶段拆成多轮小功能发布、不每完成一页就停下来索要下一步**。全部业务、权限、恢复、后台和无头验收一起交付。

这是在已有社区能力上增加个人整理和作品传播。当前源码 `7c5ad5a` 已有三种上传、数字链接、明确选版发布、搜索/标签/作者筛选、私有收藏、版本说明、练习预览、评论论坛、通知、作者关注与动态、精选公告及后台，本轮不重做这些功能。

以下默认值与产品取舍是本规划的建议，尚不是用户已确认的偏好。继续沿用社区 React Router/Hono、PostgreSQL/Drizzle、现有加密私有日志与公开控制事实、packages/ui，不迁移框架或新增服务。

## 2. 完整用户体验

### 2.1 我的谱库与私人谱单

- 增加 `/me/library` 作为个人谱库入口，包含“收藏”和“我的谱单”；现有 `/me/favorites` 继续可用，收藏仍是原有数据，不把旧收藏自动公开或迁移为新谱单。
- 创建、改名、修改简介、删除私人谱单；名称 1–60 个 Unicode 字符，简介最多 500 字符，纯文本。默认私有；每账号最多 100 个非删除谱单，每单最多 200 首，不允许同首重复。
- 从谱面详情、收藏、作者作品、关注动态和公开目录加入谱单；目录和收藏支持多选。选中状态可跨分页保留，但仅在当前账号、当前标签页内存中，最多 200 首；改变搜索条件保留并明确显示“已选 N 首”，可一键清空。
- 新增、移除、按数字编号/标题查找和排序；支持拖动，同时提供“上移/下移/移到位置”的键盘与触控替代，不只靠拖拽。
- 整理动作使用明确设置语义和预期修订号；重复请求不重复入单，并发旧页面收到冲突后保留编辑内容、提示刷新，不静默覆盖另一设备。
- 批量操作以单个目标谱单为事务边界。超过限额、不合法或不可授权的新增项目使本次变更失败，返回有界的逐项原因，不悄悄保存半份；删除已失效条目始终允许。
- 仅可新增当前公开可访问谱面，不把作者自己的私有草稿纳入可分享集合。既有条目后续撤回/下架时保留无内容占位，允许本人移除；不展示旧标题、曲绘、作者或文件链接。

### 2.2 明确发布的公开谱单

- 在私人编辑页提供“发布谱单/更新公开版本/撤回”操作，先预览公开名称、简介、顺序和可用条目再确认。私有保存绝不自动改变公开内容。
- 采用私人草稿与公开快照两层。公开快照只含此次明确确认的名称、简介和有序谱面引用；不含私人操作记录、收藏时间、关注关系、账号内部字段或未保存编辑。
- 首次公开成功分配从 1 开始的独立数字编号，公开地址 `/lists/1`；内部 UUID 不作新公开 URL。撤回、删除不复用编号，失败事务不承诺无缺号，编号不是权限凭证。
- 公开谱单始终展示每首的**当前公开版本**，不固定或重新开放历史版本；同一首更新后提示当前版本号，并直接进入现有预览/下载。发布快照固定的是谱面集合及顺序，不是文件副本。
- 发布/更新要求至少 1 首可用，保存时复核全部条目的当前权限；已经失效的项由预览明确列出，用户移除后再发布，不静默删项。发布后的条目后来失效则显示“暂不可用”无内容占位；页面可保留，其说明文字按独立公开内容管理。
- 未发布、撤回、删除、作者待注销/注销、被管理下架的谱单，对普通访客统一不可访问。所有页面/API/SEO/复制/下载重新走相同授权，不能靠收藏或事件快照继续读内容。
- 作者主页新增“公开谱单”；`/lists` 提供标题关键词、创建者数字编号筛选和公开更新时间排序，每页 20 条、稳定游标。首页仅增加紧凑入口与最近公开谱单区域，复用现有主站式卡片，不新增排行榜或算法推荐。
- 分享用现有原生分享/复制链接方式；匿名可浏览与下载，登录后可“复制为我的私人谱单”。复制预览明确列出可用/失效数量，确认后只复制当前可用引用，原作者修改不会同步改动复制品。
- 新谱单发布不触发作者更新通知；现有作者提醒仍只针对已定义的谱面/文件版本事件，避免悄悄扩大订阅范围。本轮不加谱单评论或单独订阅。

### 2.3 下载中心：与主站接近的进度体验

- 新增 `/downloads` 和全局紧凑下载浮层。谱面详情、目录选中项、私人收藏/谱单、公开谱单共用同一个任务引擎；站内跳转不丢任务，页面返回时能看到同一进度。
- 每批最多 50 首；启动前显示首数、各项状态和总字节数。匿名也可使用，但下载记录与媒体只在当前设备，绝不上送为“用户下载历史”。
- 单首与逐首批量下载保留作者上传的原始 ZIP 字节，不从预览三种资产重拼文件；不能丢掉原谱包内其他文件，也不把原始 ZIP 改名当作 ADX 转换。
- 批量提供两种明确操作：“逐首保存原始 ZIP”和“合并保存 ZIP 集合包”。集合包在外层 ZIP 中存放 `编号/原始.zip` 与 `manifest.json`，不解压、不改写内层原包。界面和帮助明确它是多个原包的集合，解压外层后逐个导入，**不宣称是一份可直接导入的 maimai/ADX 谱包**。
- 外层集合包首版最多 50 首、原始字节总量最多 128 MiB，浏览器 Web Worker 内以 STORE 方式生成，不做重复压缩；上限内还需检查可用存储预算，不满足则保留任务、提示改用逐首保存。超限不是静默删文件或冒充完成。
- 同时最多 1 个活动批次、2 个原包网络请求；遵循现有公开下载全局 16/每 IP 2 并发上限，不为了客户端吞吐放宽生产池。相同版本相同原包在本设备活动队列中去重。
- 每首状态：排队、获取中、暂停、已就绪待保存、保存已请求/文件已写入、版本变化、不可用、失败、取消。只有 File System Access 写入明确完成才能显示“文件已写入”；普通 Blob 下载仅显示“已请求浏览器保存”，不能声称知道用户实际保存成功。
- 暂停取消活动 fetch、丢弃未完成文件的内存片段；继续从完整原包边界重试，不承诺跨刷新字节续传。网络离线暂停，恢复网络后等待用户继续；429 遵循 Retry-After，临时 5xx 每项最多 3 次退避重试。403/404/410 不自动重试。
- 集合包只有全部选中项完整且校验通过才提供保存；任一不可用/失败不会自动跳过并报告成功。用户可明确排除失败项后创建一份新选择，结果清单准确记录本次包含项。
- 移动端或不支持目录选择器时，逐首下载进入“待保存”列表，由用户逐项点击；不依赖浏览器允许连续自动弹出 50 个下载。支持目录选择器的浏览器可在用户手势后选择目录并逐文件写入。
- 单个原包超过 128 MiB，或其完整文件将超过本轮 128 MiB 本地缓存/Blob 预算时，不进入内存聚合：有目录写入能力则流式保存并增量校验，否则退回现有原始 ZIP 浏览器下载并仅报告“已请求保存”。此类大文件不参与集合包、不承诺页面进度或刷新恢复；多首缓存总量按同一全局预算管理。

## 3. 下载版本、鉴权与本地存储的硬边界

目前 `/:id/download` 指向最新原包；单凭这个 URL 做队列会在作者更新时下载错版本。本轮必须一并补齐：

1. 有界的只读计划接口 `POST /api/v1/download-plans`：最多 50 个公共数字 ID，以请求正文承载，不写数据库、不签发下载权、不增加公开短链；经统一公开查询返回当前 versionId、size、SHA256 和受约束的同源下载路径。用户匿名也能调用，沿用 CSRF/速率/正文大小控制。
2. 为原包下载增加可选 expectedVersion 校验。在现有公开鉴权后于同一解析结果比对；不一致返回 409 `CHART_VERSION_CHANGED`，不能靠 expectedVersion 读取旧版本。旧的无参数下载链接兼容不变；不能先查当前版本再调用一个独立的“取任意旧版本”入口。
3. 任务固定当前 versionId/原包 SHA256/size；字节数与摘要不符即失败，不能保存截断文件。版本变化暂停该项，显示“有新版本，重新加入下载”，不自动把新版本字节或标题接到旧任务。
4. 获取每项、使用本地完整文件继续任务、生成集合包和点击重新保存前，均重新校验当前可访问且版本未变。已开始的网络流与用户已保存的文件无法远程收回，不承诺撤回后删除设备文件；服务端不发长期直链或绕过现有公开池。
5. IndexedDB 只保留完整原包检查点和最小任务计划，未完整的字节不落盘；最多 128 MiB、8 个未完成批次、24 小时 TTL。完成集合包生成不再额外把外层 ZIP 存入 IndexedDB；关闭/释放后可由完整内层文件重新生成。
6. 字节缓存按 `(scope, publicId, versionId, sha256)` 隔离；scope 是当前登录账号或匿名，凭据不存入任务。退出、账号切换、待注销或手动“清空本机记录”立即中止旧任务、释放 Object URL，并清除旧 scope 的元数据与文件。另一个标签页用 BroadcastChannel 传播失效，任务消费前仍核对 scope；跨标签页仅一个活动执行器，可用 navigator.locks，能力不足时仅当前页运行且禁用自动恢复，避免双份任务。
7. IndexedDB/配额失败时明确提示“刷新后需重新下载”，允许当前页的有界内存流程或普通原始 ZIP 链接，不把持久化失败静默当作恢复成功。下载历史只留最近 8 次最小计划，不保留完成文件；当前设备可一键清空。
8. SHA256、ZIP 生成和批次处理使用有界 Worker；取消/离页/退出清理定时器、流、worker 与对象 URL。普通页面导航保留全局执行器，硬刷新不自动联网续下。首版不引入 Service Worker、离线整站或常驻后台下载。

`manifest.json` 仅含 schemaVersion、生成时间、有序的数字谱面编号、versionId、原始字节数、SHA256、包内相对路径和对应规范公开页路径；无账号、token、对象存储 key、私有谱单 ID、关注关系或服务端绝对路径。包内文件名仅用安全数字编号，不使用作者可控名称。完整图谱/正文与预览媒体不写入本地下载历史。

## 4. 内容管理、私有性与恢复一次做好

### 数据模型与共享边界

- `chart_lists`：内部 ID、owner、修订、私有名称/简介、删除状态与时间；`chart_list_entries`：有序 chartId 引用；`chart_list_publications`：独立公开快照/修订/数字编号。唯一约束阻止重复条目；变更锁定单个谱单，不锁全库。
- 所有个人谱库 SSR/API 均 private/no-store/noindex，React Query 键包含当前账号；公共页面不把登录者的收藏/谱单归属混进共享 HTML。
- 公共成员数据通过现有公开查询的一次有界批量解析获取，分页 20 条，不对每个条目分别打数据库查询；曲绘及下载继续独立鉴权。谱单 200 首上限允许一次修改的完整有序列表，但公开展示仍分页。
- 复用现有公开内容事实与加密私有控制日志的基础设施。新种类采用独立、严格版本的 `private_library` 私有事实以及 list 公共发布/撤回控制实体；具体类型声明和表拆分由实现者在该边界内确定。绝不把私有草稿、成员操作、下载记录写入 public community_content。
- 不修改已有 private_social version=1 的含义来塞入谱单；所有未知种类/版本仍拒绝，增加兼容预检和恢复读者后才允许新写入。数据库迁移编号在实现时取下一个可用号，不硬编码占用其他分支的编号。

### 耐久性与备份恢复

- 私人新建/编辑/增删/排序/删除与发布/撤回均先提交有修订的事实，再越过适用的现有导出屏障，才能答复“已保存/已发布/已撤回”。导出失败返回明确待确认，重试幂等，不显示伪成功。
- 更新单个谱单携带完整有界草稿或必要状态，整单删除留最小 tombstone。每次公开操作有唯一操作 ID，公私记录关联；写公开快照与其权限控制在同一数据库事务，不出现快照可见但撤回控制尚未耐久的成功状态。
- 恢复沿用先控制事实、后投影内容的顺序。最新谱单删除/撤回、账号 cutoff、谱面撤回/封禁优先于旧备份；重新构建引用时不复制旧标题或重新授权旧版本。未确认耐久屏障时关闭谱库写入/谱单公开能力，已有普通谱面浏览继续按原规则工作。
- 注销使本人私人及公开谱单立即失效，后台有界清理；取消注销不会恢复旧公开分享，原私人内容仅依既有账号保留政策处理，新建账号不继承旧清单。注销 cutoff 必须作为恢复控制保留，不能靠删除所有投影行代替。
- 导入旧备份时没有谱单即为空，不从收藏猜测公开内容。下载任务与字节属本机缓存，不进生产备份；本轮完整恢复演练要覆盖私人顺序、删除、撤回、下架与旧读者拒绝。

### 举报与后台

- 复用举报类别、处理状态、限流和管理审计，新增受严格类型校验的目标 `list`，避免与 chart 数字 ID 混淆。被举报的是公开名称/简介/编排，不自动下架被引用的其他作者谱面。
- 在 `/dash/lists` 提供公开谱单查询、快照检查、下架及恢复；复用当前用户 1 管理员机制，不创建第二套角色系统。管理员不可浏览别人私人谱单。
- 下架为独立管理控制，作者重发/改名不能绕过；恢复只恢复已审核的同一公开修订，撤回或删除后的快照不可被管理员恢复成公开。谱单作者会在既有通知中心收到处理结果，采用幂等投递，不广播给关注者。
- 后台运行页只给谱单总量、公开量、控制待处理和恢复就绪聚合指标；不输出成员关系、下载历史、原始事实正文或设备标识，不增加下载统计埋点。

## 6. 一个任务内的实施顺序

下表是同一次交付的依赖顺序，不是几批小发布。开发期间撰写必要的边界覆盖并静态检查，**不逐项运行测试/安装/构建**；准备生产时集中执行。

| 阶段 | 连贯产出 | 主要代码入口 |
| --- | --- | --- |

## 7. 集中验收与正式完成条件

### 发布前隔离环境的写入和故障验收

- 谱单：新建/批量加入/去重/排序/冲突/100×200 上限；收藏不变；匿名/别人的账号不可读写私人内容；退出和换号无缓存串号。
- 分享：私人保存不改公开快照；首次公开分配数字号；撤回不复用号；复制只含确认后的当前可用项；作者更新、撤回、管理员下架/恢复、待注销及取消注销的行为符合上述规则。
- 下载：50 首/128 MiB/并发限制、重复任务、离线、暂停继续、截断/错误摘要、429/5xx、版本变动、撤回、取消，均不报告伪成功或绕过权限。
- 本机状态：刷新只有完整原包可恢复；过期/配额满/IndexedDB 禁用可降级；多标签页不能重复执行；退出/账号切换中断旧任务并清缓存；无选择器的移动端能逐项手动保存。
- 集合包：文件路径安全；内层与作者原包逐字节相同；manifest 无私有信息；失败项不偷偷跳过；生成可取消，资源释放符合上限。选用较小但覆盖边界的 fixtures，不给 CI 生成无意义的大容量文件。
- 治理：普通用户不能管理，管理员不能看私人谱单；列表下架不影响所引用的谱面；作者不能重发绕过下架；处理通知只投递一次。
- 迁移与恢复：先对生产现有记录做只读基线和事务演练；真实 fresh-volume、真实角色与有界磁盘恢复验证旧备份之后的私人删除、撤回、账号 cutoff 与下架控制，不只对 SQL 行数。
- 浏览器：沿用完整隔离 Chromium fixture，形成 A 建单并发布 → B 浏览/复制/下载 → A 私人编辑不影响公开 → 更新公开 → 撤回/下架 → B 旧任务受阻的完整流程；中英日、320/390 与桌面、键盘、长标题/空/失败状态同时覆盖。生产不创建这些测试业务记录。

### 正式发布门槛

1. 开发期间不跑测试；发布窗口所有重型验证只在指定 Linux 构建机或 CI。按项目脚本先集中验证，复用最终候选 CI 结果，核对最终合并树。
2. 现有收藏/用户/谱面数字编号及旧 UUID/用户名链接均保持；迁移前备份成功；确认新的私有事实读者兼容后才启用新写入。保留兼容恢复镜像，不能自动回滚旧读者。
3. 使用 `python3 scripts/remote/community-deploy.py` 完整部署。保留源码可读模式、私有 .env/工具/日志权限及 sparse-checkout 所需包；沿用已修复的部署路径，不绕过非 root 辅助进程。
4. 把“个人谱库页面/接口与公开谱单匿名列表/权限拒绝”和“下载中心空态/能力降级/后台谱单入口及状态”加入生产只读 smoke 与强制 REQUIRED_STEPS、代理路径白名单及负向收据测试。只读计划 POST 不加入生产桥接器白名单，不在生产真实保存谱包；真正的计划创建、字节/打包校验在上述隔离 E2E 覆盖。
5. 生产没有现成公开谱单时：公开列表验证空态；通过语法合法但不存在的 ID 验证拒绝，不编造真实样本。公开详情/复制/下架写入的完整证明来自隔离浏览器，不把生产空态称为完整写入验收。存在公开样本时追加详情只读验证。
6. 新旧强制场景全过、临时会话撤销、helper/隧道清理、三角色身份稳定，正式收据接受后才推进发布完成标记；最后检查就绪、控制屏障、编号、旧链接及发布后完整备份。
