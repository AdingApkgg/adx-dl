# 完整大任务规划：创作者工作台、批量导入与版本校对

日期：2026-10-19。状态：**规划提案，待用户整体确认；未开始产品实现、测试、推送或生产变更。**

## 1. 一次交付的目标

让作者完成一条连贯流程：准备多个谱包 → 逐项确认是新作品还是现有作品的新版本 → 有界批量上传并保存私人草稿 → 查看检查结果并定位到谱面语句和预览 → 对照旧版及当前公开版本 → 整理本次更新说明 → 明确选择并发布 → 在公开页确认结果。

建议作为持续 **14–22 小时量级**的一个完整任务，另留统一验证、修复与正式发布窗口。这个时间是范围估计，不是时限承诺。内部依赖分工不等于拆成多轮小功能发布；工作台、导入、校对、版本对照、发布与验收一并交付。

上批已经打通访客的发现、谱库整理与下载，本次补足作者反复修谱和发版的工作流。选择作者工作台的理由是三种上传、版本和显式发布已有基础，可以连续改进真实操作；统一搜索扩展、跨设备练习记录留作后续独立主题。本规划不把几个主题都塞进同一任务。

以下功能取舍与默认上限是本规划建议，尚不是用户已经确认的产品偏好。继续沿用 React Router/Hono、PostgreSQL、现有存储角色和谱面引擎、packages/ui；不新增搜索集群、编辑器服务或服务端转码服务。

## 2. 当前基础与实际缺口

基线为上一轮已验收的 `b6e6840`，本次读取的是该版本源码，不重新探测生产服务。

已经存在：

- `.adx`、`.zip`、零散资产组装及单谱文件夹导入；分片上传、摘要校验、取消和账号隔离的上传恢复记录。
- 私人谱面及版本、版本号、切换当前私人版本、删除保护、简介/署名/标签、版本更新说明和明确选版公开。
- 当前每账号最多 50 首作品（包含已公开作品的私人底稿）、每首最多 20 个版本；原包最大 64 MiB、展开总量最大 128 MiB、原包最多 128 项、maidata 最大 1 MiB。
- 服务端包校验、带难度及可选行号的警告、引擎解析上限；预览、密度时间轴、A–B 循环、倍速、镜像及 GIF 导出。
- 公开谱单、下载中心、作者更新通知、举报与后台、加密控制事实、正式发布及登录态无头验收。

缺口是这些能力目前主要分布在单首详情页：作者不能先安排一批导入映射，不能把警告、源码语句与预览位置连起来，也不能有界地对照两个私人版本，再把对照结果用于发布确认。

本次增强这些已有能力；不会把“版本列表”“更新说明”或“循环预览”重新当成新功能交付。

## 3. 完整用户流程

### 3.1 作者工作台

新增 `/me/workbench`，成为作者处理作品的汇总入口；保留 `/me/charts` 和已有详情链接。

- 汇总私人作品数、已公开数、私人内容与公开快照不同的作品、当前版本有检查警告的作品、当前设备待处理导入。所有数量来自本人已有数据；不增加浏览量、下载量或成绩埋点。
- 提供可组合的状态筛选、标题检索和稳定分页，每页 20 条。卡片显示当前私人版本、当前公开版本、更新时间、警告数量、配额与版本名额，直接进入校对或发布。
- 区分“有私人修改”“已公开”“被下架”“公开状态待确认”；查询失败显示可重试错误，不能伪装成空工作台。
- 后端一次有界批量查询摘要，不在工作台请求所有原包或逐首执行解析。待处理导入是本机信息，不与云端作品计数混成一种数据。

### 3.2 批量导入与明确映射

新增 `/me/imports` 和跨站内页面保留的紧凑导入浮层，单首入口也接入同一上传调度与身份失效机制。

建议首版上限：**每批最多 10 个原包，总原始字节最多 256 MiB；当前设备仅保留 1 批未完成计划，24 小时过期。** 单个原包及账户/版本限制继续沿用现有值，不为批量功能放宽。

- 可以一次选择多个 `.adx/.zip`，每个文件明确代表一首作品。既有零散文件/单谱目录方式仍可逐组加入这张计划表，不按相似文件名猜测组装关系；首版不做任意目录树自动识别多首作品。
- 每行先选择“新作品”或明确指定“给我的某首作品新增版本”；默认新作品。不能凭同名标题、文件名、音频或相同曲绘自动合并作品。
- 提交前显示条数、总体积、目标映射、账户剩余配额和已知版本名额。发现超出批次/账户上限、目标无权限或重复映射时，保留计划供修改；此时不开始上传或创建作品。
- 同批不允许两行同时追加到同一作品，避免隐含的版本顺序与修订竞争；作者可先完成该行，再发起下一次追加。同批 SHA256 与大小均相同的原包提示去重并阻止重复提交；同名但内容不同的原包保留为两行，不据名称判断相同。
- 只允许 1 个活动文件执行打包/摘要/上传，分片并发沿用现有上传器。最多 1 个本地打包或摘要任务；文件流式读取，不将 10 个原包同时转成 ArrayBuffer，也不把原包放进 IndexedDB。
- 每行独立显示：待确认、排队、打包/校验、上传、媒体处理、就绪待保存、草稿保存中、已保存、结果待确认、暂停/需重选文件、失败、取消。
- 上传及媒体处理成功后，用户明确勾选“保存所选就绪项为私人草稿/版本”。可以一次确认多行，但**逐行事务、逐行结果**；某行失败不回滚其他行，也不能把部分成功称为整批成功。不会批量自动公开。
- 新建与追加复用现有 sourceFileId 唯一绑定、幂等与 revision 保护。丢失响应先查实际绑定；不能盲重试产生重复作品/版本。追加基于确认时的目标修订，409 后保留行与文件，须查看最新状态并再次确认，不能自动提高预期修订。
- 调度串行执行仍须在每行实际开始、预约及保存时重新验证配额/名额；预检不是资源预约，也不保证作者另一设备随后不消耗配额。配额变化使受影响行暂停，已成功行保留。
- 单行取消只回收该行未绑定上传，整批取消逐行报告清理结果。已经保存的作品不因取消队列而被删除；删除作品仍走原有独立确认流程。

本地恢复仅保存有界计划元数据、目标 ID/预期修订、上传 ID、fileId、摘要、大小、期限和逐项结果，不保存凭据、原始文件字节、源码或资产。

- 硬刷新后不自动联网续传或创建草稿。已就绪文件经本人服务器状态复核后可再确认保存；未完成上传要求重选文件并匹配完整 SHA256 和大小，不能只匹配文件名。
- 已保存结果的本地记录只用于确认同批状态；服务器记录缺失/删除、上传过期或旧备份恢复后，显示当前实际结果，不凭本地记录重新创建已删除作品。
- 账号切换、退出、待注销清空旧 scope，停止打包/请求/保存回调；跨标签页只允许一个上传执行器，使用 Web Locks 或具有逐操作 fencing 的 IndexedDB 租约。
- 收到跨标签页身份失效后，只有重新成功确认当前身份才能恢复；身份刷新失败时保持隔离，不能拿旧的 me 缓存重新激活旧 scope。
- Web Locks 和 IndexedDB 均不可用时关闭可恢复批量模式，保留原有单首当前页上传。IndexedDB 配额失败明确说明“刷新后需重新选择”，不能显示恢复成功。不会引入 Service Worker 或浏览器关闭后的后台上传。

### 3.3 检查报告、Simai 语句与预览定位

新增本人校对页 `/me/charts/:id/review`，可选择已有私人版本查看，无需把所查看版本设为当前版本。

- 将已有服务端包检查结果整理为清晰的错误/警告/信息：缺少资产、不可预览难度、BPM 回退、未识别语句、复杂度限制等。必须区分“包被拒绝”“可导入但有警告”“仅预览能力有限”。
- 对已通过导入的版本，按需读取经鉴权的 maidata，在有界 Worker 中生成语句位置映射、难度概览与诊断定位；服务端校验仍是准入依据，本地分析不能代替它。
- 被拒绝的原包仅显示既有有界错误，不为了展示报告在浏览器重新解开任意坏 ZIP，也不保留已回收的非法原包。
- 提供只读 Simai 语句栏、行号/难度、当前位置高亮、点击或键盘定位、手动滚动暂停跟随及“恢复跟随”。定位复用既有播放/循环和密度时间轴，点击语句不默认开始播放。
- 语句定位只使用引擎解析结果和 TimingTimeline；变 BPM、首拍偏移及四拍前导与现有预览保持一致。主站的独立简化语句扫描器可参考交互，不能直接充当新的权威时钟或第二套语法解析器。
- 扩展中央解析器的可选语句/source-span 采集接口，默认调用行为不变；所有预览和新分析继续使用同一纯归一化函数。必须有归一化文本到原始输入的映射，包含 BOM、CRLF、大小写头部、传统正文及多难度段落。
- 显示位置使用原始文件 1-based 行/列；内部 offset 可采用 UTF-16 索引，转换显示时不能拆开代理对。既有诊断行号可能是难度正文相对行，不能直接冒充原文件行号；无法可靠映射时仅显示难度与诊断码并禁用跳转。
- 没有音频、诊断无时间位置或难度不支持预览时，仍能看只读文本和报告；不能编造跳转位置或强行启动渲染器。
- 公开的当前版本预览也可复用只读语句栏，但仅经当前公开鉴权读取该版本资产；本人完整报告与版本对照不公开。撤回后新读取失败，不增加历史源码入口。

报告和映射是当前会话的派生数据，不写成新的公开内容、服务器历史或跨设备笔记。

### 3.4 私人版本对照

新增 `/me/charts/:id/compare?left=<versionId>&right=<versionId>&difficulty=<n>`，仅本人可访问。默认左侧当前公开版本（没有则前一个私人版本）、右侧当前私人版本；允许选择同一作品下仍存在的任意两个版本。

对照分成三个可解释的维度：

| 维度 | 实际比较内容 | 不能推断的内容 |
| --- | --- | --- |
| 原包和资产 | 原包 SHA256/大小，maidata、音频、曲绘的 SHA256/大小/存在性 | 未预览额外文件的逐项变化、原包等价、内容安全性 |
| 包内摘要 | 难度增删、包内标题/曲师/谱师/等级、现有解析音符数与时长、BPM 序列和诊断变化 | 官方定数、作品质量、难度优劣、作者真实身份 |
| 源码 | 按难度的有界只读语句增删改、格式变化与可定位片段 | 完整语义等价、玩法正确、任意大谱面的逐音符精确匹配 |

- 两个历史版本比较的是各自不可变原包及导入摘要。现有作品级私人元信息没有完整历史快照，不能反推当时的私人简介/署名；界面明确这一点。
- 原包字节不同而已解析资产相同，显示“原包变化，已检查的预览资产相同”，不宣称整个包没有变化。归一化源码相同也不等于原包相同。
- 限制 worker 输入为每侧最多 1 MiB maidata，单次仅 1 个解析/对照任务；先处理一侧并保留有界摘要/映射，再释放其完整解析对象，不同时保留两份完整渲染场景。
- 精细语句对照预算建议每侧 20,000 个语句单位、最多 1,000 个差异块、最长 5 秒 worker 运算；到上限明确退化为摘要及两份独立源码查看，不能截掉后半部分后显示“完整比较”。两份源码全文最多 2 MiB，视图虚拟化，搜索结果最多 200 条并提示上限。
- 超过 50,000 个语句映射点时关闭精细源码跟随，保留现有预览、摘要和独立文本查看；不通过抬高 100,000 音符/1 小时的既有解析限制解决展示负载。
- 同时仅 1 个 Canvas 播放器、1 个 AudioContext、1 份已解码音频。左右切换先暂停，分别保留本侧位置；不默认认为两个版本的秒数/拍号一一对应，不做双音轨同步播放。
- 切版本、换难度、导航、退出和取消中止旧任务，释放 Worker、播放器、音频、定时器及对象 URL。每个异步结果携带账号、作品、两个版本、资产摘要与分析算法版本，过期结果不能更新新页面。
- 同时修改或删除版本时重新鉴权并提示刷新。已知旧版本不能经公开查询或 expectedVersion 被重新开放；当前公开访问规则、谱单和下载固定版本行为保持原语义。

### 3.5 发布前校对与结果核对

增强现有显式发布区域，将校对结果串起来，保留原有单首发布动作。

- 汇总此次选择版本、当前公开版本、包内差异、**已保存的**待发布标题/曲师/简介/署名/标签/版本说明、诊断以及原包公开确认。
- 校对是辅助，不引入“所有警告必须清零才能发布”的新规则；没有音频、不支持某难度等仍按现有服务端准入规则处理，作者明确知情即可。对照超预算也不等于禁止发布，显示未完成精细对照的事实。
- 可以从已完成的有界摘要生成本地“更新说明草稿”，由作者编辑并明确保存。它不自动写入版本、不自动声称修复问题、不把私人绝对路径或完整源码塞入更新说明；已有更新说明不会被覆盖。
- 确认绑定作品修订、选定版本、已保存元信息和当前公开状态；任一变化使确认失效。查看旧版不改变当前私人版本，保存私人元信息不自动更新公开内容。
- 发布仍走现有服务端权限、ready/配额、下架控制、revision 和耐久导出屏障。浏览器检查报告不能充当权限令牌或绕过管理员下架。
- 丢失响应或导出待确认显示“核对发布结果”，先读实际状态；禁止看到超时就盲重发。发布成功显示规范数字链接，并提供打开公开页核对入口。
- 版本发布与元信息更新通知继续沿用现有事件定义和幂等去重；批量导入、查看报告、对照和生成说明草稿都不发送通知。不增加“批量全部公开”、定时发布或自动回滚到旧版本。

## 4. 数据、隐私与恢复边界

- 工作台/导入/校对/对照路由和本人 API 一律 private、no-store、noindex；缓存键包含当前账号，不把私人摘要、文件名或源代码写入共享 HTML、公共搜索和日志。
- 指纹接口仅返回本人版本的内容摘要、大小、媒体类型等最小字段，不返回对象存储 key、绝对路径、签名长期链接或其他用户信息；逐版本鉴权，不能只验证 chartId。
- 导入计划属于本设备，保存成功的作品及版本仍是现有服务器真相。新工作台不引入第二套版本表或复制原包，不另建“云端上传历史”。
- 分析算法/归一化映射为纯派生状态，首选不修改现有 format=1 预览包和耐久协议；旧版本由按需读取现有资产派生，不为上线全库重处理或改写旧原包。
- 原包仍逐字节保留；三种已有输入方式的打包规则和原始 ZIP 下载语义不变。摘要相同不越过现有上传所有权、逻辑配额或 sourceFileId 绑定约束。
- 预计新增业务表不是必要条件。若实现中确需持久化业务状态，必须先补严格事实/读者/恢复协议；不能用一张临时结果表悄悄承诺跨设备或超出备份 RPO 的耐久性。普通索引迁移由实施者据查询计划确定，取届时下一个迁移号。
- 注销使工作台和私人版本入口立即不可用；取消注销不恢复旧公开分享。本机队列不能让旧控制事实、已删版本或旧账号资产复活。
- 恢复继续采用现有控制优先、原包校验、派生重建和开放屏障。导入计划、检查报告、源码对照缓存不进生产备份；新功能不会提升现有私人修改的备份恢复点承诺。
- 后台管理员沿用原有聚合运行状态和公开治理权限；不能进入其他作者的私人工作台、报告或对照页。本轮不扩张管理员读取私人原包的能力。

## 7. 统一验收与发布完成条件

### 隔离环境功能与故障验收

- 完整 A 作者链路：混合多个 ADX/ZIP 加入计划 → 明确新作品/追加目标 → 单行失败不阻塞其他行 → 就绪后明确保存私人结果 → 定位警告与源码 → 旧新版本对照 → 编辑保存说明 → 明确选版发布 → 访客只读当前公开版本。
- 重复点击、丢失响应、断网、409、配额/50作品/20版本/10行/256MiB边界、取消和孤儿预约回收；不得重复创建、自动覆盖新修订或取消已保存作品。
- 多标签页执行器互斥、租约失效后旧写入被 fence；切号/退出中断旧任务，晚到响应不能写入新 scope。刷新无文件句柄时明确重选；IndexedDB/锁不可用、记录过期有真实降级。
- 中文/英文/日文，320/390与桌面；长文件名、长标题、空态/失败态、键盘定位、手动滚动恢复跟随、暂停时切版。作者工作台私有，普通用户和管理员均不能读另一作者数据。
- BOM/CRLF/传统正文/多难度/变BPM/首拍偏移、非法语句、未知难度、没有音频、同摘要不同原包、仅格式变化、资源变化、未解析额外文件、超预算diff。无法映射则明确不可定位，不显示错误音画位置。
- 取消分析/切版/离页能释放 Worker/音频/对象URL/定时器；重型结果不晚写到新页面。对照不会暗中切换当前版本、公开旧版、改原包或下载中心版本身份。
- 新导入及作者校对不广播；显式发布仍按原事件规则仅一次。草稿/公开分离、管理员下架不能由新流程绕过；版本删除保护和旧数字/UUID链接保持。
- 真实 PG/S3/媒体/control 与有界磁盘跑新卷恢复：控制事实优先，已删除/下架/撤回不可由旧工作台或本地记录复活；现有原包仍逐字节可读。派生报告可重算，不要求恢复本机计划。

### 正式部署门槛

1. 最终候选在远程集中通过静态检查、类型、必要单元/数据库/DOM、生产构建、HTTP及完整隔离Chromium，复用最终CI结果；实际恢复和角色/WAL检查保留。测试辅助环境结束后清理磁盘、容器、卷及合成凭据。
2. 先做生产只读基线和必要迁移事务演练，再做切换前完整备份。核对现有用户/谱面/谱单编号、三种上传和既有发布语义不变；无迁移时明确记录“无新增迁移”。
3. 扩展生产只读桥接器、smoke及 REQUIRED_STEPS：作者工作台/导入页空态与本人只读数据、本人版本检查/对照只读入口及权限拒绝。每新增强制组均有缺失即拒绝的收据测试；不能只改浏览器脚本不改正式收据要求。
4. 生产不创建上传/作品/版本、不写更新说明、不发布、不做真实文件保存；完整写入和故障证明来自隔离环境。已有合适本人版本时做只读检查，缺少第二版本则说明并验证合法不存在ID拒绝，不能伪造“生产完整对照成功”。
