# 谱面详情、论坛与创作者工作台 UI/UX 完整改造

用户要求继续参考 Web 主站，统一完善这三个高频页面，开发期间不跑测试，发布窗口集中验证修复后走正式部署。基于已上线 UI 外壳和 pre 文档提交 45cd742，沿用现有 React Router、TanStack Query、Paraglide、@astrodx/ui 和主题变量；不引入依赖、迁移或新业务功能。

## 参考与问题

只读对照 apps/web 的 ChartDetailPageView、ChartDetailActions、ChartComments：分层的作品信息、明确的动作区、难度条目直达预览、正文可读行宽。论坛及工作台没有主站一一对应业务，复用主站的内容密度、分区、卡片与表单规范，不迁移主站评论后端。

当前详情难度数据与播放器分离，简介/摘要/关联作品整块堆叠，作者与获取操作层级不清。论坛把板块卡、完整筛选和话题铺在同一列，主题正文缺明确内容容器，发帖表单没有分区。工作台七张统计卡平铺，待办无法直达过滤，作品行状态、版本与动作分散，空间占用只是一行文本。

## 实施决策（由实现者按现有架构确定）

1. 谱面详情保留原始返回状态、公开快照和懒加载播放器。信息区分作品/作者/获取；增加本页锚点导航（预览、作品信息、难度、评论、推荐），不隐藏任一区内容。难度摘要变为可扫描的卡片，支持的槽使用真实按钮派发已有 community-preview-seek 事件，携带 chartId/versionId/difficulty/ms=0，播放器自动加载、聚焦，避免新 URL/全局状态。不支持槽保留数值及原因，不可操作。复用 ChartSummary 的可选回调，私有编辑仍只展示摘要。技术版本 ID 保持折叠，下载仍原 ZIP。
2. 论坛采用桌面内容列+板块侧栏，手机板块导航在筛选前可见；主搜索/排序/未回复直接可见，谱面编号筛选放原生 details。板块切换保留 q/sort/unanswered/chart，清 cursor；增加清除筛选。置顶与普通讨论分组，话题行突出标题、回复量和作者，标题仍是唯一主链接。主题页保留可用/已撤回/只读/恢复的完整状态，正文和回复分区，单一分享入口，真实锚点跳到回复；不改变举报/编辑/撤回/订阅及未保存草稿保护。发帖编辑器仅重组字段、字数、预览与动作，不改变幂等、冲突版本或校验。
3. 工作台总览收敛为总数/私有/公开/待更新四个关键值；待处理、诊断、下架状态放待办入口，复用现有查询筛选。总览与待办保留所有七类计数。显示服务端 quotaBytes、usedBytes、reservedBytes，不硬编码容量；用语义 meter 表示已用+预约，数值和容量明确，零容量不除零。作品列表呈现标题/艺术家、状态徽标、私有最新与公开版本对照、诊断数、更新时间；编辑是主动作，校对/对比/发布仍显式可达。提示新版本仍私有、发布需明确确认。不添加一键发布、自动上架或跨账号本机导入信息。
4. 三页统一小标题、辅助文案、可读宽度、响应式间距和 44px 主操作；中英日文齐备，沿用颜色/减少动画设置。长标题、长作者、未知时长/作者/诊断、空数据、网络错误均保持可理解的退路。不建立模拟业务数据到生产。

## 验收与发布

开发只改代码与必要回归源、执行轻量静态检查，暂不测试/构建/安装/预览。完成整个任务后切换发布窗口：指定构建机集中 lint/types/Bun/DOM/build/HTTP，GitHub CI 原生浏览器与隔离恢复，修复实际失败。增加真实 UI 验收：槽卡选择正确第6槽、目录锚点/返回状态、论坛带查询切板/清除/高级筛选、主题和发帖可读性、工作台待办过滤/版本状态/容量/窄屏。

正式流程保留备份、PR/合并树核对、部署、全部现有 19 组生产登录态无头门禁；在原有 UI 组内扩展上述页面只读验收，不依赖用户 Chrome、不发送生产帖子或修改发布状态。上线后核对原始谱面/配置/旧链接、角色及临时会话清理，再做备份。只有受测代码和生产门禁均通过才报告完成。实体手机/真实软键盘与浏览器视口仿真分开记录。
