# 登录、账号设置与后台管理 UI/UX

用户要求参考 web 主站，将登录、账号设置和自制谱后台作为完整大任务实施；开发期间不运行测试，上线前集中验证修复，走正式部署和生产无头门禁。日期使用用户时区 Asia/Shanghai 的 2026-10-24。

## 方式与目标

沿用 React Router、TanStack Query、@astrodx/ui 和现有身份/治理 API，参考 apps/web/src/components/site/site-settings-panel.tsx 的分类设置、共享选择器、留白和说明层级。已上线社区的导航、卡片、44px操作、主题和三语言为共同标准。本轮实施选择复用现有架构与控件；重建独立后台框架会改变认证/草稿/发布协议且增加依赖，逐页只改配色又不能解决层级问题，均不采用。这是现有产品的完整展示与交互整理，不是新增认证或治理系统。

## 页面设计

### 登录

保留稳定h1与回跳、reauth、callback错误规则。桌面为简洁说明区和登录操作区，手机按标题、方式导航、登录表单顺序排列。Google/AWMC合并进同一外部授权区，不把AWMC缺省误当故障；QQ显示可用状态、机器人提示、验证码/重试；通行密钥区保留显式登录、注册和原有自动填充生命周期，注册不折叠或卸载，以免改变Turnstile/条件认证行为。用短文说明登录后回原页面与登录后可管理绑定，不显示含令牌的next查询串。不自动跳到第三方授权、不新增弹窗授权行为。所有异步按钮仍有忙碌与失败恢复。

### 设置

/settings/profile 与 /settings/account 共用当前页导航。资料页展示本人身份、公开主页入口，头像与昵称/简介各自成区，保存/上传结果仍由原逻辑反馈，公开影响用简短说明。账号页用清楚的当前账号摘要和本次加载的登录方式/会话数量；绑定、通行密钥管理、设备会话、退出和注销分区，可页内跳转。设备卡片保留当前设备标识和可下线动作，长名称截断规则不变，服务端最后一种登录方式保护和重新登录要求不变。注销保持原有数字ID确认、默认不删除内容和冷静期，放在最后独立警示区，不额外折叠关键字段或新增未授权协议。

为避免账号切换时旧loader内容与新me组合，两个设置loader绑定当次userId，当前me不匹配时不显示旧私密内容；表单以该身份为key。只改变路由展示数据，不改变服务端DTO或缓存协议。资料保存后的后端规范化、头像预约/幂等/恢复、退出失败留页等原逻辑保留。

### 自制谱后台 /dash

继续使用用户1及现有管理角色；主站后台不改。保留唯一全局h1、管理员编号和刷新，补充上下文说明。桌面分组侧栏、移动折叠导航展示当前页面。各子页统一h2、说明、真实本页数量（仅有items时），不把分页数量当总量。

概览保持真实全站指标，增加用户、内容、治理、运行备份的常用入口。运行页按“依赖与角色 / 登录与任务 / 内容服务 / 日志与备份”分组与页内导航，使用既有ready/status值，不从计数0推断健康、不改变未知备份为成功。用户、谱面、举报、讨论、谱单、推荐、公告、治理、申诉、审计页共用标题/空态和处理面板外观；已有查询条件随URL回显，改变筛选清cursor，分页保留范围；无后端能力的筛选不新增假控件。谱单搜索保留status/publicId/ticket等独立定位条件，给出显式清除，不静默丢失工单上下文。

所有下架、隐藏、解封、公告发布、推荐保存、申诉、举报、板块操作保留原有显式确认、原因、revision、草稿/冲突比较、审计与重新认证边界。仅改变布局与相邻说明，不偷偷默认确认或重发写操作。

## 共同约束

- 不新增依赖、数据库迁移、API契约、登录渠道或角色权限。
- 不在Mac运行安装、构建、预览、全套测试或浏览器回归；开发期间仅代码/静态审阅，测试留集中窗口。
- 保留no-store、账号注销态、数字ID与旧链接、原件/公开快照、预览、备份、NapCat覆盖及异常监控。
- zh/en/ja同步；320/390/768/1280无横向溢出，主要按钮/链接/summary至少44px，长文本换行，明暗及减少动画沿用共享设置。
