# 社区治理与站务运营 — 完整任务设计

2026-10-20。用户已选择推荐范围并要求连续实现、集中验证后正式部署。本设计中的实现细节由执行者确定，延续现有 Bun / Hono / React Router / PostgreSQL / Drizzle 与共享 UI；不更换技术栈。

## 目标与交付

把现有谱面、评论、论坛、公开谱单的分散治理串成一个工作流程：管理员查看统一待办与超时积压 → 转到现有原始证据与处置页面 → 使用现有带确认的处置和结案接口 → 作者在私有处理中心查看与自己有关的处置并提交申诉 → 管理员复核并反馈 → 通知回到私有处理中心。后台同时提供站务计数、积压年龄和操作记录。一次交付、一次发布。

参考仓库 Web 主站与 apps/dash 的共享组件、概览卡片、信息层级、状态说明和结果回读。社区后台仍位于 adxc 的 /dash，绝不复用主站后台的管理员权限或部署配置。

## 范围与边界

- /dash/governance：三类举报（谱面、讨论、谱单）合并按时间排序，按来源/状态筛选，固定20条游标分页。只列编号、类别、状态、创建时间和原处理页链接，不复制举报正文或过期证据。现有处置入口继续有效。
- /dash/appeals：私有申诉队列、理由、对应决定、复核结果；open / upheld / review_required 三态。管理员近期登录才能处理，明确填写1–500字反馈并确认。
- /dash/audit：不可经应用编辑的操作记录；记录事件种类、对象类型/编号、公开管理员编号（能读取时）和时间，不记录正文、举报人身份、凭据、IP或浏览轨迹。按种类/时间分页。新版本开始记录，历史记录不伪造补全。
- /dash/governance 中运营概览：当前未结举报及申诉数、超过72小时待办数、最旧未结时间、24小时结案/操作数量与统计生成时间。这些是业务记录计数，不是访问量/DAU或代理故障推断。
- /me/governance：仅当前活动账号的管理决定和申诉历史；可针对已持久化的谱面下架、讨论隐藏/锁定和谱单隐藏决定提交一次申诉（理由1–1000 Unicode码点）。不展示其他人的举报材料或管理内部理由。每账号最多5个未结、24小时最多5条；重复请求返回已有申诉，不重复通知。
- 复核维持原处置（upheld）或需要重新评估（review_required）。复核结果通过现有 outbox 通知；不会改变任何公开可见性。需要重新评估不是自动恢复的许可，管理员仍须使用对应内容原有能力处理。谱面与讨论的终局下架/隐藏没有新增恢复通道。
- 三语言、320px/390px/桌面、键盘可用、账户切换立即移除旧身份私有数据；管理和个人接口及文档始终 private,no-store/noindex。旧 UUID/数字链接、公开搜索、上传、预览、下载、备份规则保持兼容。

## 数据与一致性

新增治理申诉表（UUID，申诉人外键级联删除，决定引用的类型/ID，唯一 user+decision，文本与状态、revision、时间）、最小操作记录表（UUID，事件类型/对象类型与ID、管理员公开编号和时间）。不拷贝原内容、证据或内部理由。申诉引用先验证当前账号是该决定的接受者；谱面旧下架从 chart_moderations+charts 当前所有者关联，必须已过现有 journal 导出屏障。讨论/谱单从 discussion_decisions 获取；原内容被清除后仍只显示公共处置理由，不恢复正文。恢复旧快照后，缺少对应决定或决定不匹配时禁止创建申诉。

原处置、三类举报结案、公告保存/发布/撤回、推荐位及申诉处理，使用数据库事务触发器写最小操作记录，业务回滚就没有记录，幂等返回就没有第二条。管理员编号来自原决定或 user_public_ids；公告/推荐的既有表不含操作者时操作记录明确显示“未知”，不推测身份。任何后台读取操作不产生操作记录。

新申诉与操作记录属于 PostgreSQL 快照备份的数据；延续现有私有举报/通知的快照恢复边界，不假称逐事件跨快照恢复。原下架、隐藏、注销、推荐等控制权仍由既有持久 journal 决定。旧备份恢复会丢失快照之后的申诉/操作历史，但绝不因申诉或审计缺失重新公开内容；文档与恢复验收明确这一区别。账户物理清除级联移除申诉文本，操作记录不保留内部 user ID，只保留公开编号与非正文事件元数据。

## 写入、并发与失败

接口会话检查、活动账户检查、admin allowlist 和近期登录复用现有服务。申诉写入与账号锁同一事务；唯一键防并发重复，revision+行锁防管理员覆盖彼此结果。所有状态转移要求 expectedRevision；相同结果重试返回已保存结果，不同结果返回409。客户端结果回读未确认前不清草稿。提交时锁定字段，账户变化/导航卸载后不接受旧回调或显示旧文本。提交结果未知时再次读取同一决定的申诉，不自动重复创建。

统一列表只读 SQL UNION ALL，(created_at,id,source) 稳定游标；游标包含筛选和当前账号范围，最多4096字节，错误返回400。所有SQL参数化，列表最多21行，reason受Unicode和控制字符限制，不新增外部服务/包/全文引擎/自动处罚/封禁权限/私信/邮件。

## 验证与发布

开发仅准备用例，不运行测试、安装、类型检查、构建或浏览器。准备发布时在指定构建机一次集中执行现有完整检查及新迁移/事务回滚/权限/跨账号/并发幂等/三来源分页/申诉通知/账户清除/旧快照恢复回归；修复真实失败。重负载任务使用现有资源上限和串行构建保护，不在Mac启动。

隔离原生 Chromium 验证完整写流程及移动三语言；生产仅只读登录态验收（新增治理工作台、作者处理中心、后台审计与申诉组），所有现有17组和谱面1第6槽继续强制。必须新增组缺失即拒绝 accepted 的负向用例。发布前备份、迁移事务演练、最终受测树与CI/合并树一致后运行正式 community-deploy.py；验收通过才能 accepted，撤销临时会话清除辅助容器，发布后备份并核对 serving/source/accepted。

保留构建机 GitHub 异常监控及健康监控；第三方节点原因调查已按用户指示收束，不阻塞本任务。
