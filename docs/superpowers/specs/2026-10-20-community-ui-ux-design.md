# 自制谱社区整体 UI/UX 整理

用户已取消下一批试玩功能，明确要求直接参考Web主站优化当前混乱的整体界面。本轮只调整信息架构、视觉和已有交互，不增加业务功能或改权限/数据模型。开发阶段未推送生产；用户随后明确授权推进生产发布。

实查：主站紧凑导航、分组更多菜单、明确的首页主视觉与内容卡片；社区三层页头、重复搜索/导航、重复发现列表、16项头像菜单、窄列后台和平铺12项管理按钮、详情页预览晚于评论/推荐、技术UUID显著、缺页脚。

落实：
1. 统一页头品牌与宽度，主导航仅发现/谱面/谱单/论坛；搜索用入口，首页只保留一处搜索；帮助/目录/公告/下载等归入更多和页脚；移动端4项底部导航，44px触控与safe-area。
2. 个人空间按谱库、创作、交流、账号分组侧导航，手机可折叠；头像菜单只保留核心去向和账号动作；后台按概览/内容/治理/运行分组侧导航，权限依旧由原loader守卫。
3. 首页主视觉+今日谱面+单组最近公开，空目录不占大段空间，移除重复账号卡片、重复导航、过时分阶段开放文案及API版本。
4. 卡片/标题/说明/表单/按钮统一层级，内容宽度按浏览/工作区/阅读划分，深浅色与强调色沿用共享token。详情预览前置，技术版本信息收进可展开区；论坛/工作台/通知统一工具栏和状态。
5. 每个既有页面仍能从导航到达；路径、查询/分页/返回状态、数字/旧链接、上传/下载/发布/通知/身份隔离均保留。底栏不盖下载队列，锚点避开sticky header，减少动画设置生效。

开发期间不执行测试、安装、构建、整库类型检查或启动预览。只准备必要回归源和静态检视；进入生产发布窗口后再在指定构建机集中验证、修复，沿正式部署及登录态无头门禁。设计阶段的浏览器只读查看用于参考；新版运行与生产验收在用户授权的发布窗口另行完成。

实施顺序是一次完整改造：外壳与导航→首页与发现→谱面详情/卡片→个人/创作/后台→三语言/手机/静态审阅。独立全分支审阅一次；发布验证与上线状态以[验收记录](../../verification/community-ui-ux-2026-10-20.md)为准。
