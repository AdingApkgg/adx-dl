# 自制谱社区内容与互动首版：连续开发大任务

日期：2026-10-18。状态：待用户确认范围的完整设计，尚未实现本文件的新功能。

## 任务规模与交付方式

这是一项围绕作者发布、访客找谱、讨论反馈和管理员处理的完整产品任务。按约 8–16 小时级别的连续源码开发量组织工作；这是范围粗估，不是耗时承诺。实现中若现有架构与设计存在实质冲突，先记录影响和可行取舍。发布前集中验证、修复和生产验收单独安排，当前三批未验收代码也纳入同一候选。

内部拆分里程碑只用于断点续做、控制依赖与保存提交。用户确认本设计后，连续完成整个范围；普通实现选择自行决定并记录，不在每个小功能后重新征求继续许可。真实阻塞、影响产品范围的变更、不可逆操作或发布授权才需要交回用户决定。

本轮用户只要求规划。本文中的新增范围和默认值均为助手建议；尚未获得实现或部署授权。

## 交付后的完整流程

作者上传或更新谱面，在作品工作台补齐介绍、署名和标签，查看所选版本与当前公开版本的差异，填写更新说明后明确发布。访客从首页、标签和搜索找到当前公开版本，查看作品资料，预览练习、收藏或下载，并对该版本发表评论。作者或回复接收者在站内通知看到新反馈；管理员能处理评论举报、隐藏违规评论、管理首页精选和公告。撤回、账号注销和备份恢复继续遵守可见性限制。

## 1. 作者工作台与发布资料

沿用 `/me/charts` 与 `/me/charts/:id`，增强现有页面，不创建重复的第二套作品管理入口。

### 私有编辑

- 可按曲名、草稿/已发布状态筛选自己的作品；游标绑定账号和条件，每页 20 条。
- 补充作品介绍（0–2000 Unicode 码点）、署名/来源说明（0–1000）、标签（最多 8 个，每个 1–20 码点）以及所选文件版本的更新说明（0–1000）。曲名和曲师沿用现有限制。
- 介绍、署名与更新说明均为纯文本和换行，不解释 HTML、Markdown 图片或嵌入内容。保留已有文件内谱师字段，明确区分上传者、曲师和各难度谱师。
- 标签采用 NFKC、首尾空白清理和英文大小写折叠后的规范键，展示保留清理后的原文；规范键去重，拒绝控制字符、斜杠和 URL。标签由作者填写，首次不预置流派字典或审核新标签。
- 所有保存使用既有 revision 乐观并发；响应丢失时读回核对，冲突保留本地输入并显示差异，不静默覆盖另一标签页的数据。
- 对未保存输入提供离开提醒；不默认把私有作品正文存入 localStorage。保存、发布和上传进度分别显示。

### 选版、比较、发布

- 同屏显示当前公开版本与待发布版本：版本号、文件大小、音频/曲绘有无、难度、等级原文、音符数/时长摘要、介绍、署名、标签和更新说明。不能解析的摘要明确标为未知。
- 比较基于已存在的导入摘要及元数据，不进行完整谱面语义 diff，不把摘要相同当作文件内容相同。
- 更新说明绑定私有文件版本，发布时连同当前作品资料复制进公开快照；后续私有修改不改变公开页。
- 保留“明确选中版本 → 核对将公开内容 → 提交”的流程。更新公开介绍/标签也需再次发布该版本，不增加自动发布。
- 当前公开页只显示当前快照的更新说明与文件版本号。本任务不开放历史版本下载、历史说明列表或旧版资产接口；旧文件仍按已有私有版本规则管理。

### 既有数据

新增字段默认空字符串、空数组；旧发布无需用户手工补资料仍可浏览和下载。回放旧权限事实时按空新增字段解释，不能从最新私有草稿补出公开内容。

## 2. 首页、发现和作品详情

- 首页提供搜索入口、最近公开更新（最多 8 首）、管理员精选（最多 6 首）、当前公告和上传/帮助入口，复用 web 主站卡片、层级、响应式及暗色样式。
- 搜索继续在服务端执行；已有曲名/曲师/发布者/数字编号查询上，补充公开标签与公开摘要中的难度谱师姓名检索。谱师姓名匹配不等于其拥有站内作者账号。
- `/charts` 加标签过滤（首版一次选择一个标签），与关键词、难度、作者、排序一起写入 URL 并绑定分页游标。保留最近公开更新、首次发布最新两种确定排序。
- 标签入口放在卡片与详情中。标签建议接口只返回当前可公开作品使用的前 20 个匹配项；查询最长 20 码点，无全量下载索引。标签标签使用次数只统计可公开作品。
- 相关作品以共同公开标签数量排序，同分按公开更新时间和 ID；最多 6 首，排除当前谱面和不可见目标，无标签或无匹配时只给作者作品入口。作者与目标都经过现有可见性规则。
- 详情补齐介绍、署名、标签、当前更新说明、难度谱师和作者入口，保留已有预览/练习、收藏、下载及举报。
- 精选只是一组有序引用，不复制作品标题、封面或作者资料。引用失效立即不展示，数量不足就少展示，不回退旧快照。
- 扩展现有 canonical、三语链接、Open Graph 标题和描述，分享正文仅来自当前公开快照。复制的是数字规范链接，不附带浏览分页或私有返回状态。
- 暂不新增 sitemap、动态分享图片或公开缓存层；沿用现有按请求重新鉴权。三语、手机和返回列表状态属于完整交付范围。

## 3. 当前版本评论与回复

### 谁能操作与展示什么

- 登录且账号 active 的用户可评论；匿名用户可读当前可公开版本下的可见评论。作者对自己作品的回复有“发布者”标识。
- 评论绑定 `chartId + publishedVersionId`。用户提交时携带正在看的版本，服务端确认仍是当前公开版本；版本变化返回冲突，保留输入并提示刷新。
- 新版本发布后默认讨论区只展示该版本评论；旧版本评论不通过猜测版本 ID 单独查询。重新明确发布同一版本时可展示仍合法可见的该版本讨论。
- 通知和评论锚点只定位当前公开版本：若目标不在已载入页，按评论 ID 解析其根与有界上下文后定位；服务端仍从当前公开版本约束查询，不提供任意旧版本查询能力。失效目标显示不可访问状态。
- 一级评论加一层回复。对回复再回复统一落在同一根评论下，以“回复用户”标识目标，不递归嵌套。
- 根列表每页 20 条，按创建时间和 ID 正序；每个根先展示最多 3 条回复，其余独立游标加载，每次 20 条。游标绑定谱面/版本/根/查询上下文。
- 正文 1–2000 Unicode 码点，纯文本、换行；不渲染 HTML、图片、提及解析或自动链接，不抓取外部链接。不开放匿名留言、附件或私信。

### 并发、限额和重试

- 每次创建由客户端生成幂等键；同一账号同一键只能产生一个评论，重试取回原结果。编辑使用 comment revision。
- 每账号全站 10 秒内最多 1 次新评论/回复，每滚动 24 小时最多 50 次创建，现存未删除评论最多 1000 条；创建与上限核验在同一账号锁下完成。编辑每条每分钟最多 5 次，不突破正文限制。
- 可编辑自己的未删除、未隐藏评论；界面显示“已编辑”，不公开历史正文。作者删除是最终状态，回复结构所需时仅显示无作者、无正文的占位。
- 根被删除不删除别人的合法回复；被回复目标消失后显示通用标识，不引用其旧正文或昵称。渲染时重新确认当前账号身份公开状态。
- 账号进入注销等待期即隐藏其评论正文和公开身份；取消注销可恢复未被删除/下架的评论。最终注销清除其评论正文、个人通知和私有举报；必要的结构占位不携带身份。

### 举报与处理

- 评论提供独立举报目标；沿用现有举报页面/处理队列的交互，但用显式 target type 区分谱面与评论，不将评论举报偷偷转换为整首下架。
- 举报分类沿用现有四类，说明 1–500 码点；每人每评论最多一张举报单，与谱面举报共享每 24 小时 10 单/最多 20 张未结的账号限额。原有谱面举报去重契约保持兼容。
- 普通用户不能借举报读取已隐藏正文；提交重试仅能取回自己的原票据。管理员可查看举报时原本公开的证据快照，按私有证据保留策略处理，不进入通知正文或公开接口。
- 证据保留采用本方案建议默认值：自动复制的被举报评论正文最多保留到举报创建后 30 天，结案或重新打开都不延长；举报人或被举报评论作者最终注销时提前清除正文快照。证据可随私有票据存储，必须独立记录被举报作者内部 ID 与不可延长的到期时间，并接入双方注销清理。到期后管理员看到“证据已清理”，仍可根据当前可见内容和举报人说明判断，不能回退恢复旧正文。
- 上述 30 天限制针对系统自动复制的评论正文；举报人填写的说明和结案记录沿用私有票据契约，随举报人最终注销删除，不把任意自由文本中的引用误称为已自动清除。涉及被举报人的系统身份字段在其最终注销后去标识化。
- `/dash/comments` 可按谱面、待处理举报、可见/隐藏状态分页。管理员“隐藏评论”需要近期登录、明确确认和原因；首版不恢复原评论、不批量删除、不封号。错误操作通过新评论和公开说明纠正。
- 隐藏评论与结案是独立操作；标为已采取措施要核对已持久化的评论隐藏事实。重复与并发请求不得制造两个最终结果。

## 4. 站内通知

- 新增私有 `/me/notifications`，页头未读数，20 条/页、全部/未读筛选、单条已读和“本页全部已读”。不做轮询推送，进入页面和本人操作后刷新，首页角标最多每 60 秒按需刷新一次。
- 首版事件：作品作者收到当前版本的新一级评论；被回复用户收到回复；举报人收到自己的举报结案；评论被管理员隐藏时作者收到公开处理原因。自己对自己的操作不通知，相同事件与收件人去重。
- 评论可见性提交成功后才生成通知；采用数据库事务内 outbox 与现有任务运行器可靠派发，不另建消息服务。
- 每条通知保存事件类型、目标 ID、收件人、事件 ID/时间和已读状态，不保存评论正文、曲名、头像或昵称快照。展示时解析当前可访问目标；不可见时只显示通用“内容已不可访问”并去掉跳转。
- 管理员内部处理备注不发送给用户；“对用户的原因”是独立的 1–500 码点纯文本字段，保存在管理决定中。管理通知引用该决定，而非被隐藏评论正文；本人可在私有通知详情读取给自己的原因，即使评论已隐藏，也不显示旧正文、曲名或对方身份。举报结案通知只给原举报人，不暴露其他举报人或举报内容。
- 未读按通知状态计算，“内容已不可访问”的未读项仍可手动已读。最大存储为每账号最近 1000 条，溢出按最旧事件裁剪；删除账号清除通知及待派发目标。outbox 重试先复核收件人 active 和事件/目标可见状态。
- 站内通知、私有收藏、举报等继续 `private, no-store` 和 `noindex`，退出/换账号清理本人查询缓存。无邮件、QQ/AWMC 外发消息或浏览器通知授权。

## 5. 精选、公告与帮助

### 精选与公告管理

- `/dash/featured` 管理最多 6 首公开作品的顺序和移除；保存时按完整有序列表与 revision 校验，去重并重新鉴权。失效引用在后台显示数字编号和不可用状态，公开端跳过。
- `/dash/notices` 支持草稿、明确发布、撤回、排序、普通/重要级别、生效和过期时间。最多 3 条当前首页公告，公告页每页 20 条。
- 每份公告包含中文标题（1–80 码点）和正文（1–2000），英/日可选且各有相同限制。缺译回退中文并显示回退标记，标签和界面文案仍有完整三语。
- 首版公告正文纯文本，最多一个 CTA，CTA 仅允许站内相对路径，由服务端校验；不导入主站公告、不允许任意脚本或外部媒体。
- 草稿编辑不会修改已发布公告；再次发布复制快照。管理员发布、撤回及评论隐藏都用近期登录、revision 和操作记录。
- 公告列表只展示当前有效且可公开的快照；过期不等于撤回，首版不公开历史快照。主页与独立 `/notices` 参考主站已有公告级别、排序、回退和空态。

### 帮助与导航

- `/help` 及 4 个简明专题：三种上传输入与包结构、明确版本发布/更新/撤回、预览练习/GIF、举报与账号管理。内容随代码版本发布，三语齐全。
- 在上传错误、发布核对、练习控制、举报和导航中提供相关帮助入口。提示采用已有错误码与真实限制，不写未实现能力。
- 明确：GIF 无声、变速改变音高、已经保存的文件不能远程收回、当前版本讨论与旧版本区别。
- 桌面导航与移动菜单统一加入浏览、帮助、通知入口；不增加悬浮遮挡或重复底栏。

## 6. 数据、权限日志与恢复契约

### 数据模型分组

沿用 PostgreSQL/Drizzle、Hono/React Router、现有队列与 `@astrodx/ui`。先检查 `0015` 后续序号再新增迁移，不重编号已有迁移。

- 私有作品 metadata 与各文件版本 release note；公开 publication snapshot 增加这些字段，旧事件缺失时取空值。
- 标签规范表与私有/公开引用，或等价有索引结构；公开查询只从公开快照边界获取。
- 评论、幂等键、状态/revision、父根与回复目标；评论举报扩展；评论管理员事实和私有证据。
- 通知与 outbox，带唯一事件/收件人约束和收件人/状态/时间索引。
- 公告私有草稿/公开快照、精选有序引用及变更 revision。

具体表拆分、DTO 名称、URL API 名称和组件文件由实现者按现有结构决定。所有列表有上限和稳定游标；普通页面不得做全库 N+1 身份或权限查询。

### 恢复后不复活被删除的公开内容

- 扩展现有存储日志框架，引入有版本号的 `community_content_visibility` 事实，按 comment/notice 区分实体；包含实体及关联 ID、单调 revision、可见状态、公开内容的规范 hash、必要的内部作者 ID。事实不存评论/公告正文、昵称或头像。
- 评论创建、编辑、作者删除、管理员隐藏，公告发布/撤回都生成事实。公开响应仅返回 DB 内容 revision/hash 与最新已导出事实一致、且其所有上层权限仍满足的记录。新可见性事实未导出时不宣布公开成功。
- 公告撤回后不复用同一公告实体重新公开，重新发布需新建公告 ID；首版评论也不提供删除/隐藏恢复。
- 对删除/隐藏/注销操作使用现有日志导出屏障和可重试恢复方式。响应丢失由 ID/幂等键读回，不盲目重复操作。最新事实删除或隐藏后不接受同实体重新变为 visible。
- 旧数据库备份与新日志回放组合：旧正文与新 revision/hash 不一致就保持不可见；日志不补出正文。备份之后创建或编辑的可见内容可能丢失，按既有 RPO 说明，但不得回退显示先前正文。
- 用户最终删除回放需要同时清理其评论正文、收件箱、待通知与私有举报，并使其作者身份不可解析；恢复链未完成或新事件无法识别时 fail closed，不能先对外提供旧评论。
- 谱面发布资料继续纳入现有 chart permission 快照及回放，不从私有字段拼公开正文。精选和所有通知只是引用，展示时再次检查权限。
- 通知已读和个人收藏属于普通备份数据，恢复旧备份可能回退其私有状态；不得因此恢复公共访问或重复执行管理动作。
- 评论举报的自动证据按“举报创建后最多 30 天，双方任一最终注销时提前清除”规则受控保留；普通评论删除后可在该期限内用于处理举报，前台说明这一点。服务端每次读取证据先检查固定到期时间和双方注销事实，不能仅依赖清理任务；从旧备份恢复后也不得重新显示已到期或因注销应清除的正文。

### 发布与回退

所有涉及日志的角色、导出器和恢复工具先支持新格式，再开启新写入。一次发布窗口内可分阶段上线，不能把“一个大任务”理解为同时替换全部服务。

生产迁移前先演练和检查记录差异，再备份和写入。增加表/列采用兼容迁移；产生新日志事实后，回退到支持这些事实的兼容版本并关闭新功能写入口，不能直接退回不认识新日志的旧镜像。回退保留新数据和日志。

## 完成定义与集中验收

用户延续的约束：开发期间不跑测试。实现阶段准备必要用例、记录静态审查与决策，源码完成时不声称已经可上生产。所有安装、全量检查、构建、容器和浏览器回归在指定远程构建机进行。

本大任务的源码交付必须同时具备六个阶段的页面、接口、迁移、三语、错误/空态、权限限制、恢复接入和开发记录；不能只完成 UI 或依靠临时假数据结束任务。先做一次整体静态审查，修复实质问题，保留可接力记录。

准备上生产时集中验证此前三批和本任务：

1. frozen install、i18n/路由类型生成、lint/类型检查、服务/交互/接口测试、构建；修复后按受影响范围补验。
2. 数据迁移干净库和旧库演练，日志导出/回放及首次支持新格式的兼容检查。
3. 真实浏览器走三条完整路径：作者上传→资料→选版比较→发布→更新/撤回；访客搜索/标签→作者/详情→练习/收藏/下载→评论/回复→站内通知；管理员处理评论举报→隐藏→结案通知、精选及公告发布/撤回。
4. 浏览器覆盖桌面/手机、三语、退出/切换账号、并发标签页、丢响应、任务重试和资源不可用。对所有公开列表、相关作品、评论、通知与分享信息验证撤回/下架/注销边界。
5. 新卷恢复覆盖“旧备份 + 新日志”中的作品资料更新、评论编辑/删除/管理员隐藏、作者注销、公告撤回、重复 outbox；不得公开旧正文或重复产生管理动作。回归已有上传、数字/旧链接、QQ/AWMC/绑定、存储健康与备份。
6. 测试和浏览器验收通过后给出候选提交、迁移/回退边界和验收证据，再根据用户届时授权推送部署；部署后另核对真实版本和关键入口。
