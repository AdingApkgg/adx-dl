# 社区内容发现、全站公开搜索与分享入口

日期：2026-10-19。状态：用户已于2026-10-19批准完整设计并授权连续实现、集中验证和正式发布。开发期间不跑测试。

## 1. 交付目标与工作规模

一次性交付「打开首页 → 找到想玩的谱面/作者/谱单/相关讨论 → 选中难度预览 → 加入已有谱库或下载」的完整流程。搜索、发现入口、内容元数据、分享落地和后台状态使用同一套公开可见规则，统一验证和发布；文中的工作流是同一个大任务的组成部分，不是若干小批上线。

按连续开发约 6–10 小时的工作量组织，时间是范围估计，恢复与原生浏览器验收可能延长。保持现有架构；开发期间只读改代码、编写必要覆盖及静态审阅，不执行测试、构建、安装或预览。准备上生产时在指定 Linux 构建机集中验证、修复，经正式发布门禁一次上线。

本设计的功能范围和数值限额已获用户批准；实施中的必要调整记录在本轮进度 ledger。

## 3. 用户完成的一次使用流程

### 3.1 首页与发现页

首页以找谱为主：醒目的搜索框、热门公开标签、现有编辑精选、最新收录、最近更新、公开谱单入口和「随机来一首」。已有精选和公告继续由现有 `/dash/featured`、`/dash/notices` 管理。

新增 `/discover` 汇总完整发现内容，每区最多 8 项；首页每区最多 4 项。标签最多 12 个，按当前可见谱面数降序、规范化 key 升序排列；最新收录按首次分配的永久公开编号降序，最近更新按当前公开快照 updatedAt；两者分开表达，不把编辑描述包装为新版本发布。数据不足时显示真实内容和空状态，不复制条目凑满，不显示虚构热度。

随机入口遵守当前谱面筛选，返回一首当前可见且存在非空、受支持难度的谱面；没有符合条件的作品时明确提示。每日推荐按 UTC 日期和公开编号做确定性轮换，实时移除不可用内容；不称作个人推荐，也不收集点击、下载和浏览行为来打榜。随机查询使用有界候选窗口（最多 200 首），界面称随机发现，不宣称全库均匀抽样。

### 3.2 全站公开搜索

新增 `/search?q=...&type=all|charts|authors|lists|topics`。全部结果分为谱面、作者、公开谱单、论坛主题四组，各最多 4 项，分别进入完整结果；单类型每页 20 项。不同类型不混算一个所谓统一热度分数。

- 谱面：已发布标题、曲师、作者主动公开的别名、标签、该公开版本的谱师署名、当前可公开作者名。
- 作者：当前公开名字、个人简介、数字编号；只列至少有一项当前公开谱面/谱单/论坛主题贡献的活跃账号，不暴露空白账号目录或私有草稿数量。
- 公开谱单：已发布名称、介绍、当前公开作者名，保持现有公开快照、账号 cutoff 和 moderation 语义。
- 论坛主题：当前可见标题、主题正文、当前公开作者名，显示板块；删除主题根帖后的占位壳不参与正文搜索。回复、谱面评论、私人消息和后台资料不在本轮全文搜索范围内。

默认排序为相关度；谱面还支持最新收录（永久编号降序）、最近发布（当前公开期间 publishedAt）、最近更新和标题，其他类型支持相关度、最近发布。相关度使用可解释的整数等级：当前类型数字编号精确命中 > 标题/名字精确命中 > 标题/别名前缀 > 标题/别名包含 > 作者/曲师/谱师/标签 > 简介或主题正文；同级用对应公开更新时间降序、永久身份升序打破平局。所有输入都是字面文本，`%`、`_`、引号不变成通配符或操作符。

规范化为 NFKC、首尾空白移除、连续空白合并、ASCII 大小写折叠；不自动简繁/翻译/罗马音转换。最多 120 个 Unicode code point、6 个空白分隔词，各词必须至少命中一个允许字段，不跨字段拼接制造命中。单个中文词使用包含查询。可以由作者用别名补充译名、读音或社区昵称。首版不引入模糊纠错服务或新的搜索集群。

展示命中原因（如「别名：…」「谱师：…」），正文摘要最多 120 code point。高亮通过文本片段与 React 节点实现，不把用户内容当 HTML。无结果时保留筛选，提供清除条件、标签/作者目录和随机发现；接口失败与真实空结果区分。

首页和页头的搜索联想仅在聚焦并输入至少 1 个 code point 后触发，150ms 防抖、最多 6 项谱面结果；输入法组合期间不请求，旧请求不能覆盖新输入，键盘上下/Enter/Escape 和触摸可用。不预下载完整社区目录；搜索提交始终可直接进入结果页。

### 3.3 谱面高级筛选与浏览

在现有 `/charts` 和新谱面搜索结果复用同一查询契约与组件。支持关键词、单个作者、最多 5 个标签（AND）、难度槽、最多 8 个精确标级、谱师、时长区间、仅可预览。标签/标级/谱师联想每次最多 20 项，只来自当前公开作品。

必须在同一条 difficulty summary 记录上同时满足难度、标级、谱师、时长及可预览条件：例如 6 槽的标级不能与 5 槽的谱师组合后误命中。可预览要求 `previewSupported=true` 且 `noteCount>0`；0 音符占位槽不算可试玩。时长按该槽 `durationMs`，秒级整数范围 0–3600；未知时长在设置区间时不命中。下载完整谱面仍沿用已有全部版本包，不因筛选槽而裁剪 ZIP。

标级保留作者原始字符串，规范化后按精确值筛选。`13+`、`13.3`、`78`、`13?` 等均可展示；不把作者标级转为官方定数，不推算 Rating。本轮不新增 BPM 范围，因为旧摘要没有可信统一的 BPM 数据，避免为搜索修改预览产物协议或再次重建原文件。

支持网格/紧凑列表，默认网格；视图偏好仅保存在本设备，失效时退回默认。筛选、排序、分页保存在 URL；已选条件可逐个移除和全部清除；返回列表恢复过滤和位置。列表批量选择、加入谱库和下载复用现有账号隔离 provider 与限额，不另起一套任务队列。

### 3.4 作者、标签目录与相关内容

新增 `/authors`，按名字/数字编号搜索、按名字或最近公开贡献排序，20 项/页；卡片显示名字、简介、可见贡献数和已有关注按钮。匿名保留作品可以在谱面结果中存在，但不能倒推出原作者。

新增 `/tags` 和 `/tags/:key`：标签目录仅统计当前公开谱面，详情复用高级筛选与既有相关谱面逻辑。每页 20 标签，名称和规范化 key 沿用既有 `normalizeChartTags`，链接必须 URL 编码，不新增强制类别树。

谱面详情继续显示同标签相关谱面，增加「该作者其他作品」与「包含此谱面的公开谱单」入口，各最多 6 项，去重且不列当前谱面。公开谱单归属页必须通过现有可见规则；论坛主题关联已有谱面时继续使用现有链接，不自动发帖。

### 3.5 别名编辑与公开快照

作者在现有谱面元数据编辑/发布确认中管理最多 8 个别名，每个 1–60 code point；去首尾空白、规范化去重，拒绝控制字符与无效 Unicode，按普通文本处理。别名不是 URL，也不从外部网址导入。

别名默认 `[]`。修改只保存到私有草稿；明确发布/更新公开资料后才进入搜索。发布同一版本仅改别名不触发关注者版本更新通知，不分配新数字编号，不更换 source/version/preview 指针。作者工作台标记「公开资料待更新」，确认框同样绑定 revision 和已保存元数据；并发变更要求重新确认。

别名属于公开快照的真实字段，写入 `charts` 与 `chart_publications`，DTO、完整性比较、下架证据、匿名保留、日志与恢复必须一起支持；禁止只放浏览器或搜索缓存，禁止后台直接编辑作者别名。

## 4. 分享落地、SEO 与公开订阅

谱面分享继续用 `/charts/数字`；可附加 `difficulty=1..7` 和 `t=秒`，t 有限、非负且不超过 3600，最多三位小数。落地只选择对应槽并展示「加载预览」，不自动播放、不自动下载；仅在用户加载并验证当前版本后将位置钳制到时长再 seek。槽不存在时提示并让用户选择，不偷偷切换后声称原链接有效。该链接跟随当前公开版本，不承诺旧版本定位永久不变。

论坛链接、谱单、作者主页与搜索条件提供复制链接；链接生成不含会话、私有 UUID、来源 URL 或下载 capability。旧 UUID/旧用户短号继续由现有 canonical 跳转兼容；详情页 canonical 永远不含筛选/时间参数。

补充 `/sitemap.xml` 和 `/feed.xml`：
- sitemap 仅收当前可见谱面、公开谱单和有公开贡献作者的 canonical 数字链接，以及静态公开入口；不收论坛主题、搜索组合、私有路径；每分片最多 1000 URL，分别按种类和数字区间分片，不从查询参数生成海量页面。
- RSS 按永久公开编号降序选最近收录的 30 首当前可见谱面，固定 chart 数字 URL 做 GUID；同版本改资料、撤回再发布不改变排序，不公开版本历史。现有 publishedAt 不是跨撤回期间持久的首次发布时间，不能冒充原始首发日期；本轮省略 item pubDate，不新增历史表，也不依赖关注动态的 90 天窗口。
- 搜索/筛选页 `noindex,follow`，明确 hreflang；SSR 展示首屏内容，关闭 JS 时 GET 搜索和分页仍可用；主站动画服从 reduced-motion。
- robots 不承担授权，显式不收各语言的私有/后台路径；新 XML、公开搜索、建议、统计和发现响应均 `private,no-store`，不新增 CDN/Service Worker/持久本地全文缓存。下载资产仍使用现有授权与缓存策略。

## 5. 架构、数据与权限约束

### 5.1 同一公开可见规则

查询从现有真实公开状态出发：谱面使用 `charts/publication.ts` 的完整 allowed/query 组合；谱单使用 `library/core.ts` 的 `publicListAllowed`；论坛使用 `discussions/core.ts` 的 visible/topicAllowed 和正文 hash 验证；作者使用公开身份耐久屏障、账号状态和当前贡献可见性。这些谓词须重构为模块内部可复用的只读解析器，不能为搜索抄一套简化 SQL。现有 resolved() 对 preview manifest/MD5 的 TS 验证、论坛 factMatches() 对正文 canonical hash 的验证也必须纳入，不能只导出当前 allowed()/visible() 就称完成。

建议/搜索/分面统计/目录/随机/相关/sitemap/feed 均使用相同授权，不仅结果项要过滤，计数与摘要也不能包含隐藏或未耐久内容。公开作者信息发生失效时去掉归属，不撤回本来允许匿名保留的谱面。列表、随机选择与最终详情/资源请求之间可能发生撤回，最终解析器始终重新授权。

以同一个只读 repeatable-read 事务生成一次搜索响应的实体结果、计数和分面，使其共享快照；耐久/完整性检查必须在 LIMIT 与计数之前完成，禁止先取前 N 条再过滤造成空页、假计数或漏查。不是所有用户信息都已公开：账号邮箱、OAuth 身份、关注图、私有列表、草稿、上传原文都不得成为匹配字段。

### 5.2 数据变化与恢复

新增别名草稿/公开列、必要查询索引和用于公开完整性校验的数据库纯函数迁移；不新增可信状态投影表、用户行为表、下载计数或榜单。数据库函数与现有 TS 验证对 shape、canonical hash、manifest 布局/size/NFC、MD5 等必须由同一份边界 fixture 验证等价；发现未知或不支持格式即拒绝匹配。函数版本随 schema 管理，所有公开实体继续通过同一查询入口，不允许数据库验证比最终资源解析更宽松。搜索直接读当前 PostgreSQL 公开数据，不建立一份可滞后放权的永久搜索索引。

现有 `chart-journal.ts` 的 permission/retention 是严格 v1。增加显式 v2 公开 permission 与相应 retention/下架快照格式：新写入的公开别名走 v2，旧 v1 完整保留原始校验/默认语义，公开 DTO 显示为 `aliases:[]`，不能把旧事实改写成不同 hash。新恢复工具同时读取 v1/v2；旧工具遇到 v2 拒绝恢复，不能丢弃别名后继续。所有 backup、匿名保留、注销、再发布、下架以及 preview-refresh 记录权限事实的路径必须一起升级。

迁移只给旧别名列初始化空数组，不改现有公开序号、版本、源文件、摘要、预览 hash、发布时间，也不群发通知。恢复从旧 DB dump + 新日志可恢复新版别名；较新的撤回、下架、注销 cutoff 覆盖旧快照。新日志写入后不能直接用旧恢复镜像回滚；回滚采用新协议可读的前一功能行为镜像，或保持新版本并修复，禁止静默降级恢复。

### 5.3 查询与输入边界

新 GET API：`/api/v1/search`、`/api/v1/search/suggestions`、`/api/v1/discovery`、`/api/v1/authors`、`/api/v1/tags`、`/api/v1/charts/random`、`/api/v1/charts/:id/public-lists`；旧公开列表 API 和单 tag 参数保持兼容，新增多标签参数与旧参数冲突时返回 400。

搜索/排序游标绑定规范化 query、type、全部筛选、算法版本和确定性排序键；最长 1024 字节，拒绝其他作用域及未知字段。分页读实时公开数据，不承诺编辑期间的固定快照；前端按永久身份去重，作用域变更回第一页，过期游标明确提示刷新。结果中的数字编号保持十进制字符串。

所有请求最多 20 条完整结果/类型（all 合计最多16），建议最多6条；正文与简介只取摘要。使用参数化 SQL、显式大小边界、DB statement timeout 1500ms、每次公共聚合响应总预算 2500ms；请求失败返回可重试错误，不渲染假空结果。已有公开限流策略保留，对新建议接口增加每 IP 60 次/分钟的独立预算。除现有统计外不存原始搜索词。

发布窗口用合成数据验证 5000 谱面、1000公开作者、1000谱单、2000主题的计划与耗时；以 p95 < 1500ms 为目标，超过预算先优化索引/查询，不下调可见性校验。业务过滤由数据库完成，无全量源码解析、无每结果单独查询。若数据库规范化能力与 JS 不一致，采用服务器统一规范化表达式并写等价测试，不靠客户端猜测。

## 6. 后台、运维和状态

`/dash/status` 增加搜索与发现的就绪、近一次受控性能验收结果、协议支持版本，不展示原始查询词、作者关注关系或私人列表。指标以已有可用状态为基础，不制造常驻采样/扫描任务；性能结果标注验收时间，不当作当前实时延迟。

发现模块失败独立显示不可用状态；公开谱单恢复未就绪时该组提示不可用，其余实体继续可搜索，但接口明确各组 status，不能把不可用伪装成零结果。共享只读事务内部用各组 savepoint 隔离可恢复查询错误，超出总预算则把未完成组标记不可用；不让一次 SQL 超时导致事务已失败却继续假装读取成功。单类型查询不可用返回 503；all 查询允许其他组可见并显示部分失败。不新增外部通知渠道、私信、积分、收费、官方定数、推荐模型或开放写 API。

## 7. 一个大任务的实现顺序

1. 定义搜索/高级筛选/分享参数契约，抽出可复用公开授权查询；实现别名 v2 数据、备份与恢复兼容，编写边界覆盖但不执行。
2. 完成服务端四类搜索、同槽筛选、建议、作者/标签目录、发现/随机与相关入口；准备索引和性能用例。
3. 完成首页/发现/全站搜索/谱面列表/目录/详情分享和现有谱库下载入口的整体 UI，中英日、移动和键盘一次接齐。
4. 完成 XML/SEO、后台就绪展示、帮助与隐私文案，扩充隔离浏览器与正式生产门禁；做一轮独立全变更静态审阅。
5. 进入唯一发布窗口：构建机集中验证和修复、迁移演练、PR/CI、正式部署、强制生产只读无头验收、发布后备份和资源清理。

内部可按职责提交检查点；用户只收到一个完整交付，不将半成品模块作为一批完成。

## 8. 集中验收与发布完成标准

开发期间不跑测试。发布窗口统一执行：
- 共享规范化、同槽过滤、literal query、长 Unicode/组合输入、URL往返、游标作用域、别名 draft/public/冲突和精确命中理由的单元/DOM/API用例。
- 两账号/匿名权限矩阵，撤回/隐藏/删号/匿名保留/未导出日志；同一条内容在搜索、建议、目录、计数、随机、相关、sitemap、feed 都不能留下旧可见信息。缓存恢复、后退导航与账号切换也不显示旧私有数据。
- 合成原生 Chromium：A 上传→编辑别名→未发布搜不到→明确发布→B 从联想命中→同槽筛选→预览→加入谱库/下载→搜索公开谱单/作者/论坛→复制难度时间链接→撤回/下架消失→空卷恢复后仍消失。补无 JS GET、320/390/桌面和中英日。
- 合成权限 v1/v2 混合日志、相同 revision 冲突、旧读者拒绝、新版撤回优先、匿名保留、注销撤销与真实有界磁盘 fresh-volume restore；源文件/版本/数字编号及已修复的第6槽保持不变。
- 指定构建机完整 lint/type/unit/PG/DOM/HTTP/build/native和恢复检查，性能矩阵；CI 最终树与部署树一致。正式生产门禁保留既有全部组，新增公开搜索发现组和已登录发现→谱库/下载只读组，验证缺组收据被拒绝。
- 生产无头验收不新建作者、别名、谱单、帖子或下载业务任务；使用已有公开内容检查读路径与空状态，所有写流程在合成环境完成；保留谱面1第6槽要求和原字节 MD5 检查。
- 正式协调器部署后自动跑登录态验收，全部通过才更新 accepted 标记；前后备份、账号/谱面编号、旧链接、三角色心跳、原会话保留、临时会话撤销和辅助容器清理全部核对。

完成证据必须分别记录源树、CI、迁移/恢复、生产版本、门禁收据和备份，不把设计、静态审阅或某个测试通过称为整个大任务完成。
