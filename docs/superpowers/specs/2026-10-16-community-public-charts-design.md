# 自制谱公开发布与浏览：首版设计

状态：设计候选，待确认；本文件不代表新功能已实施或获准上线。

独立 builder check 已完成：未发现影响实施计划而必须补充的产品问题。以下未由用户逐项指定的首版范围均为开发者建议，等待完整设计确认。

## 已确定的方向与本稿假设

用户选择在上传、备份恢复后优先推进「公开发布与谱面浏览」。现有基础是私有 Chart / ChartVersion、ZIP 和文件夹导入、私有 Canvas 预览、版本管理、按需存储和账号注销。沿用现有 React Router / Hono / PostgreSQL / pg-boss / SeaweedFS / 三语 UI；不改变主站 main 的发布线。

本稿由开发者提出的默认方案：作者自行发布，匿名访客可浏览、预览和下载当前公开版本；每次发布必须明确选择版本，上传和编辑始终先留在私有草稿。作者可撤回。首版不引入审核队列、搜索服务、排行榜、评论、标签、收藏、游戏兼容接口和公开历史版本。用户对完整访客流程的回答可调整这些默认值。

## 用户闭环

1. 作者登录后照常上传并保存私有谱面。在自己的详情页查看版本及预览；这些操作不会使内容公开。
2. 作者选择一个已处理完成的版本，查看将公开的标题、艺术家、谱面难度、封面、音频和 ZIP 大小，再显式确认发布。提示公开下载提供该版本的原始 ZIP，包含包中的全部文件；确认该包适合公开分享。不自动使用上传后的最新文件。
3. 匿名访客从首页入口进入 `/charts`，分页浏览最新公开的谱面，打开 `/charts/:id`，查看作者公开资料和难度、按需播放预览，并下载当前公开版本的 ZIP。
4. 作者继续编辑或上传新版本时，已公开的版本和文字保持不变。只有再次确认发布才更新公开快照。
5. 作者撤回后，列表、详情、音频/封面/maidata 和 ZIP 下载的新请求均不可访问；私有草稿仍可管理。已经下载到访客设备的文件无法由站点收回。

## 发布记录与并发

新增独立 `chart_publications` 表，以 `chart_id` 为主键，每首谱面最多一条当前公开记录。记录 `version_id`、`title`、`artist`、`published_at`、`updated_at`；标题、艺术家来自明确确认时的 Chart 快照，难度等内容来自对应不可变版本摘要。

- 用复合外键 `(chart_id, version_id)` 指向 `chart_versions(chart_id, id)`，数据库阻止发布别的 Chart 的版本。
- 发布时间用于列表排序；私有编辑不改变公开记录。再次发布时保留首次 `published_at`，更新 `updated_at`，列表按后者及 chart id 排序。
- 发布、重新发布、撤回与私有编辑共用 Chart revision；请求携带 `expectedRevision`。不匹配返回 409 `CHART_CHANGED`，前端刷新后由作者重新确认。
- 相同版本和完全相同文字的重复发布不再次递增 revision，也不把内容刷到列表顶部；重复撤回保持成功且不重新修改版本。原请求响应丢失后先 GET 实际状态，不盲目重放写请求。
- 修改遵循现有用户 → usage → storage budget → Chart / version / File 的锁顺序及 storage maintenance gate；发布操作不创建或复制物理对象、不重复计逻辑额度。
- 发布前再次检查：作者账号 active、Chart 和版本未删除、版本属于本人、File 为 chart-source/ready、原始 blob 和预览 artifact 可用、对应 hash 未被封禁。不能凭前端曾显示 ready 就发布。

私有 DTO 增加受限的发布摘要：当前公开版本、公开文字、revision 和更新时间；公开 DTO 不包含 sourceFileId、存储 key、上传会话、账号邮箱或 OAuth 资料。

## 读取与缓存边界

公开记录授予的是这一个版本的读取权限。它不改变私有 File API，也不把任意逻辑 File 或同 hash 的其他所有者文件公开。

- 匿名接口的每次详情、资产与下载请求都以当前发布记录为授权依据，并检查 Chart/version/File/blob/derived object 的有效状态和 hash block。
- 私有接口仍只允许所有者读取；知道公开 Chart id 不会获得其他私有版本或原始 File API 的权限。
- 首版的公开列表、详情、资产、下载及错误响应统一 `Cache-Control: private, no-store`、`nosniff`。公开表示任何人可读，首版不启用共享 CDN 缓存；不新增 Cloudflare purge 凭据或规则。
- GET / HEAD / Range / If-Range / If-None-Match 沿用已有资源读写规则。maidata、音频和封面从现有已校验 artifact 流式切片，响应只包含指定资产，不返回整个复合 artifact。
- ZIP 下载从发布版本的 original blob 流式读取，校验 object metadata / 原件 size / sha256；使用 `application/zip` 与 `Content-Disposition: attachment`，文件名由公开标题与 Chart id 安全生成，不使用上传时可能包含个人信息的路径。
- 未发布、撤回、隐藏、删除、不存在、非当前公开版本，对匿名请求统一返回 404。对象存储暂时不可用返回 503，不把存储地址写给访客。
- 撤回对后续请求立即生效；撤回前已经开始的传输允许结束。首版不承诺从访客设备撤销副本，也不提供不可撤回的长期签名链接。
- 复用现有 IP 限流和资源读取取消能力，为匿名下载增加小而明确的并发上限；达到上限返回可重试错误，不建立无界等待队列。具体数值在实现阶段根据已有限制确定并记录。

## API 与页面

所有页面包含现有语言前缀，下面使用无语言前缀的业务路径。

| 接口 | 行为 |
| --- | --- |
| `PUT /api/v1/me/charts/:id/publication` | 登录；`expectedRevision`、`versionId` 和公开确认；返回新的私有 Chart DTO |
| `DELETE /api/v1/me/charts/:id/publication` | 登录；`expectedRevision`；撤回并返回新状态 |
| `GET /api/v1/charts` | 匿名；有界 cursor/limit；一次查询提供公开摘要和作者展示数据 |
| `GET /api/v1/charts/:id` | 匿名；当前公开快照、摘要和明确的版本 id |
| `GET/HEAD /api/v1/charts/:id/versions/:versionId/assets/:role` | 匿名；仅当前公开版本的 maidata/audio/cover |
| `GET/HEAD /api/v1/charts/:id/download` | 匿名；当前公开版本原 ZIP；Range 支持 |

列表只做按最新公开更新时间的游标分页，默认每页 24 条、最大 50 条。游标长度和结构严格校验；没有公开条目时给出可理解的空状态。首版不做模糊搜索；后续搜索仍需遵循总体设计的多语言验证，不提前安装 Meilisearch。

`/charts` 和 `/charts/:id` 使用 SSR loader 通过 API 获取数据，不让组件或 loader 直接查库。详情页明确显示公开版本和更新时间，避免访客把当前私有版本序号当作公开版本。已有私有 Canvas 组件拆出可复用的资产地址入口，保留私有调用默认行为；引擎与音频继续按需载入。

首页和页头增加可发现的公开谱面入口。私有详情页增加公开状态、选择版本、确认发布、更新公开内容、撤回和查看公开页的入口；提交期间防重复点击，409 后保留用户意图但重新展示当前状态。中/日/英三语同步。页面沿用已有共享 UI 和布局，不另建一套视觉系统。

公开详情可以索引；元数据只使用发布快照。列表分页和错误页面按现有 SEO 规范生成 canonical/robots；不把私有页或私有资源地址加入站点索引。具体 sitemap 接入随仓库现有实现决定。

## 版本删除、账号注销与存储回收

版本和 File 的引用是持久化约束，不能仅依赖页面隐藏。

- 正在公开的版本不能被单独删除；返回明确错误，让作者先撤回或发布另一个版本。切换自己的私有 currentVersionId 不改变公开版本。
- 删除整个 Chart 时，在同一事务中撤回公开记录，再执行已有版本/文件删除协议；恢复或重试不会重新公开。
- Chart 的 `owner_id` 改为 nullable、用户外键 `ON DELETE SET NULL`。这用于落实现有“注销但保留公开内容”的产品规则，不用于允许匿名上传或管理私有草稿。
- 冷静期里，账号状态 gates 公开读：待注销作者的公开谱面暂不展示，引用保留；取消注销后恢复原公开记录。主动撤回的记录已不存在，不会因取消注销重新出现。
- 最终注销且选择删除内容：撤回全部记录，沿用现有 Chart / version / File 清理和删除日志。
- 最终注销且选择保留内容：只保留当时仍公开的版本及其发布快照；将 Chart 当前版本指针指向保留的公开版本，删除其他私有版本，随后由用户外键匿名化 Chart 和 File 所有者。公开页显示“已注销用户”，不保留昵称、头像或旧上传文件名。
- 现有 storage purge 已会保留仍有业务引用的非头像 File；扩展 charts deletion partner，让被保留公开版本继续形成有效引用，其他私有内容照常退款/软删除。不得因匿名化把仍公开的原件或预览 GC 掉。
- 逻辑容量仍按原始 File 计费；公开、更新发布和撤回均不预分配磁盘或重复计费。备份和删除日志规则不放宽。

恢复安全是本次实现范围的一部分。现有 `user_deleted` 日志只携带用户 id，恢复重放会删除该用户全部谱面/文件，不能直接用于“注销但保留公开内容”。扩展既有独立持久化日志，记录精确的匿名保留版本与公开快照；同时记录撤回、整谱删除和公开版本替换所废止的公开许可。事件必须在操作确认成功前持久化，采用现有可重试/幂等协议；日志不可用时失败关闭，不返回虚假的撤回成功。

开发者的恢复策略：恢复到更早备份时，只开放该备份中存在且最新持久化许可仍允许的版本。若 A 已被 B 替换，不得因备份只含 A 就重新公开 A；B 的原件或预览缺失时保持不可访问并报告待恢复，不从私有版本猜测替代。最终匿名保留只保留注销当时仍获许可的版本及发布快照；不得复活旧公开版本、私有草稿、作者昵称/头像或已撤回内容。恢复测试须重放晚于快照的日志并实际检查公开读取与存储引用。

## 发布边界与验证

只在独立远程测试库、合成账号和现有镜像流程验证；Mac 不安装依赖或运行应用/构建/浏览器。迁移采用 additive publication 表与明确的 owner FK 调整；首次迁移不会把任何现有私有谱面变为公开。

实现至少覆盖以下真实行为：

- 私有草稿默认不可匿名访问；发布后只放行选中版本；其他版本、其他用户 File 和存储 key 不外泄。
- 私有编辑不更新公开快照；发布 CAS、重复发布、响应丢失回读与撤回幂等。
- 在用版本删除、整谱删除、撤回后详情/Range/HEAD/304/ZIP 均重新鉴权；并发发布/删除遵守锁与外键。
- 发布前后、公开 → 撤回、账号冷静期 → 取消、最终匿名保留/删除、File sweep 与完整恢复均保持引用和隐私边界。
- 从早于撤回、版本替换和最终注销的备份恢复后，重放日志不复活旧公开许可或作者身份；最新获准版本缺失时关闭读取。
- 实际浏览器：作者发布，匿名访客从目录进入、预览并下载，再撤回；解包结果与该公开版本原 ZIP 一致，旧私有版本不可读。
- 真实 HTTP 与受控对象存储：Range 和取消、元数据不匹配、hash block、存储失败、超限/并发限流及私有缓存头。

首版的产品代码和 schema 需完成独立复核及远程验证后再进入 PR；生产发布仍需按用户明确授权范围进行，不能把本次恢复修复的上线当作新功能的上线许可。
