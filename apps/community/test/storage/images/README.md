# Safe storage image fixtures

All inputs except colors-animated-8bpc.avif are original synthetic plain-color fixtures generated for these tests. No personal photos or external avatar URLs. `manifest.json` pins exact sizes and SHA256. `generators/LICENSE` covers original generators/fixtures.

Baseline generation: `generators/generate-baseline.mjs` with its pinned Bun lock/manifest under official Bun1.4.2-slim linux/amd64, sharp0.35.5/libvips8.18.7. It writes /probe/fixtures; copy the named baseline outputs. APNG is a frozen own32x32 red/green two-frame fixture; its original generator was not retained. Its exact bytes/hash and valid chunk CRCs were verified by the preflight, and product tests exercise those bytes.

Own CMYK/GPS/HEIC: `generators/generate-sharp.mjs`, `generate-png.py`, `generate-heic.sh`; write in /fixture-output. Sharp0.35.5/libvips8.18.7 generates actual four-channel CMYK JPEG and EXIF orientation6/GPS latitude and longitude0/1,0/1,0/1. HEIC uses Debian libheif-examples1.23.4-1~deb13u1 with libx265-2154.1-2, x265 encoder parameters in the script, an own32x32 RGB PNG. These bytes were frozen and independently decoded by heif-dec and sharp metadata before vendoring. Recipe CMYK pixel expectations use actual color-managed conversion ([232,0,0] and [28,60,139]), not naive RGB expectations.

The sole upstream asset is [plain animated colors AVIF](https://raw.githubusercontent.com/AOMediaCodec/libavif/fa78ed71de0bcd35cc314393ea491e57c0eba66f/tests/data/colors-animated-8bpc.avif), AOMediaCodec/libavif commit fa78ed71de0bcd35cc314393ea491e57c0eba66f,1235bytes,SHA2562f8683d21725261f37f86e115f0c212cc52d0fefd3a2ddfcc4fa648c1859906d. Upstream tests/data/README.md assigns the same license as libavif. `LICENSE.libavif` reproduces the full generic BSD-2-Clause notice from that immutable commit. The personal-photo EXIF AVIF alternative and unclear-license rainbow HEIC are excluded.

Container inspection fails closed: PNG signature+chunk-header reads total at most4096 bytes; payloads are skipped positionally, every chunk through IEND is bounded by the actual file size, acTL rejects before decode. BMFF requires ftyp as the first box, validates normal/64-bit size and major+all compatible brands within4096 bytes, rejecting avis before decode. Missing/malformed/oversized/too-many headers are IMAGE_INVALID. Accepted static AVIF additionally requires sharp heif/av1 and exactly one page.
