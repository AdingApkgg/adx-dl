# Storage runtime setup

Production remains blocked until Task12 recovery/edge acceptance and adequate capacity. The 2026-10-11 read-only host observation was 38.41 GiB available; approved fresh worst-case demand is **71 GiB plus both dump bounds and growth**. Defaults remain 20 GiB originals, 2 GiB derived, 2 GiB S3 temporary objects, a separate 2 GiB media scratch filesystem and a 5 GiB free-space floor. Verified original staging and worst-case new restic data each add up to 20 GiB. Existing allocations are deducted only once by the live preflight. Retention can require much more; no compression/dedup/offsite guarantee is assumed.

Preserve `COMPOSE_FILE=compose.yaml:.superpowers/napcat-reuse.compose.yaml`. The deployed overlay reuses NapCat on the external network; do not start/recreate the base NapCat service, alter its volumes, use `down`, `--remove-orphans`, or replace this composition with base-only deployment.

1. Copy `.env.example`, run `ops/fill-secrets.sh`, and fill the external values and measured dump upper bounds. Existing keys are retained; output contains names only.
2. Provision a **new private disk-backed filesystem no larger than 2 GiB** at `STORAGE_MEDIA_SCRATCH_DIR`. A named Docker volume or tmpfs does not provide this requirement. On Linux, a concrete operator option is a new exclusive 2 GiB regular image file, `fallocate`, `mkfs.ext4` on that new file only, and a loop mount at a dedicated empty directory. Check the new file/mount identity and persistent mount ordering before use. These are operator steps, not executed by deploy.sh; never format an existing block device, change global quotas, or change the Docker daemon. Startup checks real statfs and rejects tmpfs/ramfs or oversized filesystems.
3. Build the app and backup images, run the migration, then `docker compose run --rm --no-deps storage-config`. It publishes role configuration mode0600 before first Seaweed start and creates an empty `.capacity` subdirectory in the object volume. Application services mount **only that volume subpath**, read-only, so statfs measures the object filesystem without exposing raw object bytes. Requires Compose volume subpath support. The initializer refuses a nonempty/symlink probe directory.
4. Start only `seaweedfs`. On first installation, explicitly run `docker compose run --rm --no-deps storage-init` once. This requires empty external restore/journal/key directories, creates a random raw32-byte0600 journal key and authenticated genesis, and writes open restore state last. It never adopts existing or closed state. Partial failure remains closed for inspection. Keep journal/key/state outside PG/S3/restic snapshots.
5. Initialize the existing restic repository independently and retain its password. Run `docker compose run --rm --no-deps backup bun ops/backup/preflight.ts`; failure blocks deployment. The gate verifies both signed buckets, actual scratch bounds and additional demand per filesystem. Bun's optional `frsize` is used for filesystem block counts; malformed metadata fails closed.
6. After Task12 acceptance, `./deploy.sh` preserves the actual old serving image under `astrodx-community:rollback-<revision>`, builds once, migrates, performs capacity preflight and updates only web/control/media. Both web readiness and the independently running media heartbeat must pass. The original 03:30 timer remains the only backup timer.

The tested Seaweed4.48 prefix ACL allows web writes only below `blobs/tmp/*`; media writes only below canonical `blobs/sha256/*` and `derived/sha256/*`. Its legacy `Write` privilege includes deletion; control's bucket-level Write permits both PUT and DELETE. Backup is Read/List on both buckets for signed readiness and has no write permission. No bucket fallback was needed. Configuration initialization sees all four S3 keys; each actual application role receives only its own key. Only control receives Cloudflare purge credentials; web/control alone share the internal media secret. The internal web listener3001 and Seaweed8333 have no host port or new tunnel.

Each role owns a dedicated PG advisory session and a current process UUID. A backup freezes those process identities and requires fresh current-owner ACKs after actual local IO drain and durable-claim checks. Missing/replaced/crashed roles or lost DB sessions fail closed. Polling reconciles released/orphan gates within bounded intervals; lease expiry or a missing HEAD is not IO quiescence. Native media work and nested writes share one reentrant tracker. Shutdown closes new admission, aborts native/HTTP work, reaps it and drops role ownership.

`bun run storage:health` inside control reports signed storage/queue/media readiness and actual purge/dead counts. `bun src/server/storage/health.ts media` is the media process health probe. Backup runs use unique0700 frozen bundles through restic and marker completion. Retention explicitly groups the fixed host and `community-full` tag across different run paths (7daily/4weekly/6monthly); it does not prune `community-db`. Unique bundle paths can reduce metadata reuse, though verified original staging still reuses immutable hashes.

Development: generate `.storage-dev/s3.json` with `bun ops/seaweed/write-config.ts .storage-dev` using locally generated role env before `docker compose -f compose.dev.yaml up -d seaweedfs`. Development data is a distinct volume and S3 binds only127.0.0.1:58333. Do not start it when the isolated acceptance fixture already owns that port.

Media rebuilds deliberately report immediate public-resume delivery as deferred: media has no internal bearer credential. The committed public publication row remains the existing fair backfill intent. Control's hourly storage sweep revalidates current generation and references and calls web's authenticated resume endpoint; failures count in `storageFailures` and rotate for retry. A repair can commit while reporting zero immediate repairs until that eventual resume occurs.
