# 生产无头验收的网络与登录态

正式入口是仓库根目录 `python3 scripts/remote/community-deploy.py`。仅在应用已切换且确认无需重建时使用 `--verify-current`；它仍须通过全部生产门禁及会话撤销，才推进完成标记。Mac 只运行控制器和 SSH 中继，Chromium 在构建机运行，不读取个人 Chrome 资料。

## 验收专用代理

默认继承生产 web 的代理。若该出口不稳定，可在生产 SSH 用户家目录配置 `.config/astrodx-community/acceptance-proxy.json`，只为临时验收容器选择机器上已有且已验证的本地 HTTP 代理：

```json
{"httpsProxy":"http://host.docker.internal:20172"}
```

这是当前 Arch 机器既有的规则代理；其它机器使用前先核对实际代理。配置必须是当前用户拥有、权限 `0600` 的普通文件；禁止软链接、外部代理主机、用户名密码、额外路径和查询。没有配置时继续使用原代理。该文件不进入 Git，不修改网站 `.env`、全局代理节点、浏览器代理或用户凭据；配置失效会阻止验收，不降级绕过检查。

## 公开预览媒体

登录态页面和私密 API 通过十分钟上限的 SSH 只读桥读取。公开谱面的 maidata、音频和曲绘按严格路径匹配后，使用构建机 Chromium 的原公网 HTTPS 与已配置代理获取；不附带桥密钥、Authorization 或会话 Cookie，不缓存媒体，每次仍由公开接口检查发布权限。私有预览路径继续使用登录桥。

不要把公开音频转发到生产桥再经 Mac 中继到构建机：这既引入额外网络路径，也可能耗尽桥的 25 秒上游限制。2026-10-24 的定向复现中，同一约 1 MB 音频在生产选中代理上 30 秒超时，而规则代理完整返回；真实浏览器路径的连续预览正常。正式 UI 门禁现要求同页连续打开、关闭两次，并在存在音频时确认响应 200 且传输完整，避免静音降级产生假通过。

## 证据与清理

正式 19 组结果、补充视觉结果分别归档，补充检查不能替代正式回执。正式流程绑定实际运行修订、工具树及脚本摘要，核对临时会话已撤销、原用户会话保留、应用未被验收过程重启后才标记完成。不要并行启动针对同一用户的多个受控登录验收，避免相互影响原会话保留检查。
